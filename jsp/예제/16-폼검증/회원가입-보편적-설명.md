# 보편적인 회원가입 Validation 설명

## 📋 개요

가장 보편적으로 사용되는 회원가입 폼의 Validation 예제입니다. 정규식을 사용하여 각 필드를 검증합니다.

## 📁 파일 구조

- **회원가입-Validation-보편적.jsp** - 회원가입 폼 (클라이언트 사이드 검증)
- **회원가입-결과.jsp** - 가입 결과 페이지 (서버 사이드 검증 포함)

---

## 🔍 검증 항목

### 1. 아이디
- **규칙**: 영문으로 시작, 영문/숫자 조합, 4-12자
- **정규식**: `/^[a-zA-Z][a-zA-Z0-9]{3,11}$/`
- **예시**: `user123`, `admin`, `test1234`

### 2. 비밀번호
- **규칙**: 영문/숫자/특수문자 각각 1개 이상, 8자 이상
- **정규식**: `/^(?=.*[a-zA-Z])(?=.*[0-9])(?=.*[!@#$%^&*])[a-zA-Z0-9!@#$%^&*]{8,}$/`
- **예시**: `Pass123!`, `Test1234@`

### 3. 비밀번호 확인
- **규칙**: 비밀번호와 일치해야 함
- **검증**: JavaScript에서 직접 비교

### 4. 이름
- **규칙**: 한글만, 2-10자
- **정규식**: `/^[가-힣]{2,10}$/`
- **예시**: `홍길동`, `김철수`

### 5. 이메일
- **규칙**: 표준 이메일 형식
- **정규식**: `/^[0-9a-zA-Z]([-_\.]?[0-9a-zA-Z])*@[0-9a-zA-Z]([-_\.]?[0-9a-zA-Z])*\.[a-zA-Z]{2,3}$/i`
- **예시**: `user@email.com`, `test.name@example.co.kr`

### 6. 전화번호
- **규칙**: 010-1234-5678 형식
- **정규식**: `/^010-\d{4}-\d{4}$/`
- **예시**: `010-1234-5678`

### 7. 약관 동의
- **규칙**: 필수 체크박스
- **검증**: `checked` 속성 확인

## 🎯 핵심 정규식 패턴 설명

### 1. 아이디: `/^[a-zA-Z][a-zA-Z0-9]{3,11}$/`

```
^              문자열 시작
[a-zA-Z]       첫 글자는 영문 (대소문자)
[a-zA-Z0-9]    나머지는 영문 또는 숫자
{3,11}         3개 이상 11개 이하 (전체 4-12자)
$              문자열 끝
```

### 2. 비밀번호: `/^(?=.*[a-zA-Z])(?=.*[0-9])(?=.*[!@#$%^&*])[a-zA-Z0-9!@#$%^&*]{8,}$/`

```
^                      문자열 시작
(?=.*[a-zA-Z])         전방 탐색: 영문이 최소 1개 포함
(?=.*[0-9])            전방 탐색: 숫자가 최소 1개 포함
(?=.*[!@#$%^&*])       전방 탐색: 특수문자가 최소 1개 포함
[a-zA-Z0-9!@#$%^&*]    허용된 문자들
{8,}                   8자 이상
$                      문자열 끝
```

**전방 탐색 (Lookahead) 설명:**
- `(?=...)`: 긍정적 전방 탐색
- `.*`: 임의의 문자 0개 이상
- 여러 조건을 동시에 만족시킬 때 사용

### 3. 이름: `/^[가-힣]{2,10}$/`

```
^          문자열 시작
[가-힣]     완성형 한글
{2,10}      2개 이상 10개 이하
$          문자열 끝
```

### 4. 이메일: 복잡한 패턴

```
^                              문자열 시작
[0-9a-zA-Z]                    첫 글자는 영문/숫자
([-_\.]?[0-9a-zA-Z])*          하이픈/점/언더스코어 + 영문/숫자 조합 0개 이상
@                              @ 기호
[0-9a-zA-Z]                    @ 뒤 첫 글자는 영문/숫자
([-_\.]?[0-9a-zA-Z])*          하이픈/점/언더스코어 + 영문/숫자 조합 0개 이상
\.                             점 (이스케이프)
[a-zA-Z]{2,3}                  최상위 도메인 (2-3자)
$                              문자열 끝
i                              대소문자 구분 안 함
```

## 📝 주요 코드 설명

### 1. 정규식 패턴 객체

```javascript
var patterns = {
    id: /^[a-zA-Z][a-zA-Z0-9]{3,11}$/,
    passwd: /^(?=.*[a-zA-Z])(?=.*[0-9])(?=.*[!@#$%^&*])[a-zA-Z0-9!@#$%^&*]{8,}$/,
    name: /^[가-힣]{2,10}$/,
    email: /^[0-9a-zA-Z]([-_\.]?[0-9a-zA-Z])*@[0-9a-zA-Z]([-_\.]?[0-9a-zA-Z])*\.[a-zA-Z]{2,3}$/i,
    phone: /^010-\d{4}-\d{4}$/
};
```

**장점:**
- 패턴을 한 곳에 모아 관리
- 재사용 가능
- 유지보수 용이

### 2. 빈 값 검증

```javascript
if(id === ""){
    alert("아이디를 입력해 주세요.");
    form.id.focus();
    return false;
}
```

**중요:**
- 정규식만으로는 빈 값을 완전히 막을 수 없음
- 명시적으로 빈 값 검증 필요

### 3. 비밀번호 확인 검증

```javascript
if(passwd !== passwd2){
    alert("비밀번호가 일치하지 않습니다.");
    form.passwd2.select();
    return false;
}
```

**주의:**
- 정규식이 아닌 직접 비교
- 두 필드의 값을 비교

### 4. 전화번호 조합

```javascript
var phone1 = form.phone1.value;
var phone2 = form.phone2.value.trim();
var phone3 = form.phone3.value.trim();
var phone = phone1 + "-" + phone2 + "-" + phone3;
```

**설명:**
- 세 개의 입력 필드를 하나로 조합
- 조합된 문자열을 정규식으로 검증

## 🛡️ 보안 고려사항

### 1. 클라이언트 vs 서버 검증

| 구분 | 클라이언트 검증 | 서버 검증 |
|------|----------------|----------|
| **목적** | 사용자 경험 향상 | 보안 |
| **우회 가능** | 가능 (JavaScript 비활성화) | 불가능 |
| **필수 여부** | 선택 | 필수 |

**결론:** 양쪽 모두 구현해야 함!

### 2. 비밀번호 보안

**현재 코드:**
```jsp
<%= passwd.replaceAll(".", "*") %>
```

**실제 서비스에서는:**
- 비밀번호를 해시화하여 저장 (BCrypt, Argon2 등)
- 평문으로 저장하지 않음
- 결과 페이지에도 표시하지 않음

### 3. SQL Injection 방지

```jsp
// PreparedStatement 사용
PreparedStatement pstmt = conn.prepareStatement(
    "INSERT INTO member (id, name, email) VALUES (?, ?, ?)"
);
pstmt.setString(1, id);
pstmt.setString(2, name);
pstmt.setString(3, email);
```
