# 1장 실습 환경 구축 — 우분투 서버 만들고 원격(SSH) 접속하기

목표는 딱 하나입니다.

- 내 PC(윈도우) 안에 **리눅스 서버(우분투 서버)**를 가상머신으로 만들고
- **SSH 원격 접속(PuTTY)**까지 성공해서
- 이제부터 “진짜 서버”처럼 다룰 수 있는 상태로 만드는 것

---

## 0. 준비물 체크

### 0.1 필요한 것

- **Windows 10/11 PC**
- **VirtualBox** (가상머신)
- **Ubuntu Server ISO** (설치 이미지)
- **PuTTY** (SSH 접속 도구)
- (선택) **공유기/랜**: 브리지 모드에서 같은 네트워크에 붙어야 함

### 0.2 최소 권장 사양(가상머신)

| 항목 | 최소 | 추천 |
|------|------|------|
| RAM | 2GB | 4GB |
| CPU | 2코어 | 2~4코어 |
| 디스크 | 20GB | 30GB+ |

> 가상머신에 너무 많이 주면 **윈도우가 느려집니다.** 내 PC RAM이 8GB면 VM은 2~3GB 정도가 무난합니다.

## 1.1 우분투 이미지(.iso) 다운로드

### 1.1.1 ISO가 뭔가요?

- **OS 설치용 파일**입니다. 윈도우 설치 USB의 “원본 설치 파일” 같은 개념입니다.

### 1.1.2 어떤 걸 받나요? (추천)

- **Ubuntu Server LTS** 권장 (가볍고 서버 실습에 표준)
  - 예: 24.04 LTS, 22.04 LTS 등

> “Desktop(데스크톱)”도 설치는 가능하지만, 서버 실습 목적이면 **Server**가 더 깔끔합니다.

## 1.2 VirtualBox 설치

### 1.2.1 VirtualBox 역할

- 내 PC 안에 “가짜 컴퓨터(가상 컴퓨터)”를 만들어서, 그 안에 우분투를 설치합니다.

### 1.2.2 VirtualBox 실행 방법 (Windows)

💻 윈도우 기준(대부분 이 방법으로 실행합니다)

- **방법 1 (가장 쉬움)**  
  - 키보드 **윈도우 키** 누르기  
  - 검색창에 `VirtualBox` 입력  
  - **Oracle VM VirtualBox** 클릭

- **방법 2 (시작 메뉴에서 찾기)**  
  - 시작 메뉴 → **Oracle VM VirtualBox** 폴더 → **Oracle VM VirtualBox** 실행

- **방법 3 (바탕화면/작업표시줄 고정)**  
  - VirtualBox 실행 후 아이콘 우클릭 → **작업 표시줄에 고정**(또는 바탕화면 바로가기 만들기)

### 1.2.3 설치 시 체크 포인트

- 설치 중 네트워크 드라이버/가상 어댑터 관련 권한 요청이 나오면 **허용**
- 설치 후 재부팅이 필요하면 **재부팅**

## 1.3 가상머신(빈 서버) 생성

VirtualBox에서 새 VM을 만드는 단계 = **“빈 서버 생성”**입니다.

### 1.3.0 자주 묻는 포인트(실습 중 막히는 것 먼저 해결)

#### A) ISO를 더블클릭했더니 DVD 드라이브로 보이는데, 이걸로 설치하나요?

- 윈도우에서 ISO를 더블클릭하면 **DVD 드라이브로 “마운트”**됩니다.
- 하지만 VirtualBox에서는 보통 **마운트된 파일 목록을 쓰는 게 아니라** 다운로드된 **`.iso 파일 자체`**를 선택해 연결하면 됩니다.

#### B) VM Name은 뭐로 짓나요?

- 추천: **`ubuntu-server-2404`**, `ubuntu-server-24-04`, `lab-ubuntu-server-2404`
- 규칙: 목적/버전이 한눈에 보이게 + 영문/숫자/하이픈 위주

#### C) “Proceed with Unattended Installation(무인 설치)”에서 뭘 체크하나요?

- 처음에는 **설치 과정을 직접 보는 게 안전**해서, 가능하면 무인 설치 옵션은 단순하게 가져가면 됩니다.
- **Install Guest Additions**: 보통 **체크 X** (Ubuntu *Server*는 대개 불필요)
- (보이면) **백그라운드에서 설치**: 보통 **체크 X**

#### D) “다음(Next)” 버튼이 비활성화예요

- 대부분 **Host Name 규칙 위반** 때문에 막힙니다. 특히 **점(`.`)** 같은 문자가 들어가면 비활성화되는 경우가 많습니다.
- 해결: Host Name을 점 없이 바꾸기
  - `ubuntu-server-24.04` ❌
  - `ubuntu-server-2404` ✅
  - `ubuntu-server-24-04` ✅

#### E) 설치는 보통 얼마나 걸리나요?

- 보통 **10~30분**
  - **SSD/사양 좋음**: 10~15분
  - **보통(SSD)**: 15~25분
  - **HDD/사양 낮음**: 25~40분

### 1.3.1 기본 생성 값(핵심)

- **Type**: Linux
- **Version**: Ubuntu (64-bit)
- **Memory**: 2048MB 이상(추천 4096MB)
- **CPU**: 2코어 이상
- **Disk**: 20GB 이상(VDI / 동적 할당 추천)

### 1.3.2 VM 설정에서 추가로 확인하면 좋은 것

- **System → Processor**: 2 cores
- **Display**: 서버는 그래픽 필요 거의 없음(기본값 OK)
- **Storage**: Optical Drive에 **ISO 연결**(다음 단계에서 설치용)

## 1.4 가상머신에 우분투 서버 설치

### 1.4.1 ISO 연결 후 부팅

- VM 설정 `Storage`에서 ISO 지정 → VM `Start`
- 우분투 설치 화면이 뜨면 정상

### 1.4.2 설치 중 반드시 챙길 것(중요)

- **username / password 설정**: 앞으로 SSH 로그인에 그대로 사용
- **OpenSSH server 설치 체크**: 가능하면 꼭 체크
  - 체크하면 나중에 `apt install openssh-server`를 따로 할 필요가 줄어듭니다.

### 1.4.3 디스크 파티션(처음엔 단순 추천)

- 실습용이면 보통 “Use entire disk”류의 기본 옵션으로 충분합니다.

### 1.4.4 설치 완료 후

- 설치가 끝나면 재부팅 안내가 나오고, 콘솔 로그인 프롬프트가 뜹니다.
- 이 상태가 **“리눅스 서버 완성”**입니다.

## 1.5 네트워크 설정 (NAT vs 브리지, 그리고 고정 IP)

여기가 가장 헷갈리는 구간입니다. 결론부터:

- 실습에서 **윈도우(PuTTY) → 리눅스 서버(SSH)**로 편하게 붙고 싶으면
- **브리지(Bridged) + 고정 IP**가 가장 직관적입니다.

### 1.5.1 NAT vs 브리지 차이(핵심만)

| 구분 | NAT | 브리지(Bridged) |
|------|-----|------------------|
| 인터넷 | 됨 | 됨 |
| 내 PC(호스트)에서 접속 | 가능(설정 필요/포트포워딩 등) | **매우 쉬움** |
| 같은 공유기 다른 PC에서 접속 | 까다로움 | **가능(같은 LAN이면)** |
| IP 느낌 | VM이 내부 가상망에 숨어 있음 | **VM이 내 PC와 같은 네트워크에 있음** |

### 1.5.2 VirtualBox에서 브리지로 바꾸기

- VM 전원 OFF
- `Settings → Network → Adapter 1`
  - **Attached to**: `Bridged Adapter`
  - **Name**: 실제로 인터넷 되는 랜카드(유선/무선) 선택
  - **Cable Connected** 체크

### 1.5.3 우분투에서 현재 IP 확인

서버 콘솔에서 아래 중 하나로 확인합니다.

```bash
ip a
```

또는(설치했다면)

```bash
ifconfig
```

대부분 `enp0s3` 같은 이름의 인터페이스에 IP가 붙습니다.

### 1.5.3.1 IP로 NAT/브리지 빠르게 판단하기(핵심)

- `10.0.2.x` → 보통 **NAT**
  - 외부(다른 PC)에서 VM으로 들어오기는 어려운 편(포트포워딩 필요)
- `192.168.x.x` → 보통 **브리지**
  - 내 PC/같은 공유기 PC에서 **SSH 접속이 쉬움**

만약 `ip a`에서 `10.0.2.x`가 나오면 아래대로 네트워크를 바꿉니다.

### 1.5.3.2 NAT → 브리지로 바꾸는 방법 (VirtualBox)

1) **VM 완전 종료**
- 우분투 화면에서:

```bash
sudo poweroff
```

또는 VirtualBox 창에서 **ACPI 종료**로 꺼도 됩니다. (중요: 저장 상태(Save) 말고 완전 종료)

2) VirtualBox에서 설정 변경
- VirtualBox 관리자 화면 → 해당 VM 선택 → **Settings**
- **Network → Adapter 1**
  - **Attached to**: `Bridged Adapter`
  - **Name**: 실제로 인터넷 되는 랜카드 선택(와이파이면 Wi‑Fi, 유선이면 Ethernet)
  - **Cable Connected** 체크

3) 다시 부팅 후 IP 재확인

```bash
ip a
```

이때 `192.168.x.x` 형태로 바뀌면 정상입니다.

### 1.5.4 고정 IP(정석: netplan)

우분투 서버는 보통 **netplan**으로 네트워크를 설정합니다.

1) netplan 파일 위치 확인

```bash
ls /etc/netplan
```

2) 파일 편집(예: `00-installer-config.yaml` 또는 `50-cloud-init.yaml`)

```bash
sudo vim /etc/netplan/00-installer-config.yaml
```

3) 예시(브리지에서 고정 IP)

아래는 예시입니다. `enp0s3`, IP 대역, 게이트웨이, DNS는 **내 공유기 환경에 맞게** 바꿔야 합니다.

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: no
      addresses:
        - 192.168.0.50/24
      routes:
        - to: default
          via: 192.168.0.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8
```

4) 적용

```bash
sudo netplan apply
```

5) 적용 확인

```bash
ip a
ip r
```

> **주의:** IP를 잘못 잡으면 SSH가 끊길 수 있습니다. 처음엔 “DHCP로 받은 IP 확인 → 그 대역에서 안 겹치는 IP로 고정” 순서가 안전합니다.

## 1.6 PuTTY로 SSH 접속(윈도우 → 우분투 서버)

### 1.6.0 PuTTY 실행 방법 (Windows)

- **방법 1 (검색으로 실행 / 가장 쉬움)**  
  - 키보드 **윈도우 키** → `putty` 입력 → **PuTTY** 클릭

- **방법 2 (시작 메뉴에서 실행)**  
  - 시작 메뉴 → **PuTTY** 또는 **PuTTY (64-bit)** 실행

- **방법 3 (설치가 안 돼 있으면 설치부터)**  
  - Microsoft Store에서 **PuTTY** 설치 후 실행  
  - 또는 `PuTTY.exe` 설치 파일(인스톨러)로 설치

#### 1.6.0.1 (참고) PuTTY 공식 설치 파일로 설치할 때

- 보통 Windows 10/11이면 **`putty-64bit-xxx-installer.msi`**(64-bit x86) 받으면 됩니다.
- 설치는 `Next → Install → Finish`로 진행하면 끝입니다.

### 1.6.1 SSH 접속 정보

- **Host Name**: (서버 IP)
- **Port**: 22
- **Connection type**: SSH

PuTTY 설정 화면에서는 보통 아래처럼 입력합니다.

- **Host Name (or IP address)**: 예) `192.168.55.193`
- **Port**: `22`
- **Connection type**: `SSH`
- (선택) 매번 입력하기 싫으면 `Saved Sessions`에 이름 입력 → `Save`

### 1.6.2 접속 성공 화면

PuTTY에서 접속하면 보통 이런 흐름입니다.

- `login as:` 가 뜬다
- username 입력
- password 입력(입력해도 화면에 안 보이는 게 정상)

### 1.6.2.1 처음 접속할 때 “Host key” 경고가 뜨는 경우

처음 접속하면 아래 의미의 경고창이 뜰 수 있습니다.

- “이 서버의 host key를 저장한 적이 없는데, 정말 이 서버가 맞나요?”

대응:

- 내가 방금 만든 서버 IP가 맞으면 **`Accept`**를 누르면 됩니다. (다음부터는 보통 안 뜸)
- 1회만 접속하고 저장은 안 하려면 **`Connect Once`**
- IP가 낯설거나 의심되면 **`Cancel`**

### 1.6.3 접속이 안 될 때(가장 흔한 원인)

- **IP 오타** (가장 많음)
- 브리지 안 됨(랜카드 선택 잘못)
- 서버에 **OpenSSH가 설치/실행 안 됨**
- 방화벽/네트워크 정책(회사/학원망 등)

서버에서 SSH 상태 확인:

```bash
sudo systemctl status ssh
```

SSH가 없다면 설치:

```bash
sudo apt update
sudo apt install openssh-server -y
sudo systemctl enable --now ssh
```

## 10. 자주 터지는 문제(트러블슈팅)

### 10.1 PuTTY가 “Connection timed out”

- **브리지 모드인지** 확인
- VM 네트워크 어댑터가 **실제 사용 중인 랜카드**로 잡혔는지 확인
- 서버 IP가 맞는지(`ip a`) 재확인
- 학원/회사망에서 외부 장비 접속 차단일 수 있음 → 집/개인 공유기에서 재시도

### 10.2 “Network is unreachable” / 인터넷 안 됨

- 게이트웨이/라우팅 확인:

```bash
ip r
```

- 고정 IP를 설정했다면 `routes`/`via`가 공유기 IP와 맞는지 확인

### 10.3 SSH 서비스가 안 떠 있음

증상 예:

- `sudo systemctl status ssh` 입력 시 → `ssh.service could not be found`

해결(아래 그대로 입력):

```bash
sudo apt update
sudo apt install openssh-server -y
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

정상이라면 `active (running)` 비슷하게 표시됩니다.

추가 확인(SSH가 22번 포트에서 듣는지):

```bash
sudo ss -tnlp | grep :22
```

### 10.3.1 화면이 버벅이거나 커널 경고(RCU stall)가 뜨는 경우

가끔 아래처럼 “멈춘 것 같은” 메시지가 콘솔에 출력될 수 있습니다.

- `rcu: INFO: rcu_preempt detected stalls on CPUs/tasks`

대부분 **VM 자원(RAM/CPU) 부족** 또는 설치/업데이트 중 I/O 부하로 잠깐 발생합니다.

해결 팁:

- VM 전원 OFF → VirtualBox `Settings`
  - **RAM 4GB 이상**, **CPU 2코어 이상**으로 올리기
- 업데이트 적용 후 재부팅:

```bash
sudo apt update
sudo apt upgrade -y
sudo reboot
```

- 부하 확인(선택):

```bash
top
```

## 10.4 (실습 로그) 지금까지 우리가 실제로 한 흐름 요약

아래는 실습하면서 실제로 겪는 “가장 흔한 흐름”입니다. 지금 상태 점검용으로 그대로 따라가면 됩니다.

### 10.4.1 IP 확인(내 서버 IP 찾기)

```bash
ip a
```

- `lo`의 `127.0.0.1`은 내부용(무시)
- `enp0s3` 같은 인터페이스의 `inet` 옆 주소가 **접속용 IP**

### 10.4.2 NAT인지 브리지인지 빠른 판단

- `10.0.2.x` → 보통 **NAT**
- `192.168.x.x` → 보통 **브리지(정상)**

### 10.4.3 NAT(10.0.2.x)였으면 브리지로 변경

- VM 완전 종료:

```bash
sudo poweroff
```

- VirtualBox → VM 선택 → **Settings → Network → Adapter 1**
  - Attached to: **Bridged Adapter**
  - Name: 실제 인터넷 되는 랜카드(Wi‑Fi/Ethernet)
  - Cable Connected 체크
- 다시 켠 뒤 `ip a`로 `192.168.x.x` 확인

### 10.4.4 `sudo`가 비밀번호를 요구하면?

- `sudo`는 관리자 권한이라서 **리눅스 계정 비밀번호**를 묻는 게 정상입니다.
- 입력해도 화면에 글자가 안 보이는 게 정상 → 다 입력 후 Enter

### 10.4.5 SSH 서비스 없다고 나오면 설치/활성화(필수 레시피)

```bash
sudo apt update
sudo apt install openssh-server -y
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

추가 확인(22번 포트 리슨):

```bash
sudo ss -tnlp | grep :22
```

### 10.4.6 윈도우에서 PuTTY 접속

- Host Name: **서버 IP**(예: `192.168.55.193`)
- Port: `22`
- Connection type: `SSH`
- `login as:` → 사용자명 / 비밀번호로 로그인

### 10.4.7 접속 후 첫 화면에서 “IPv4 address / 업데이트 개수” 확인

로그인 직후 화면에 보통 아래 정보가 뜹니다.

- **IPv4 address for `enp0s3`**: 현재 서버 IP (예: `192.168.55.193`)
- **`XX updates can be applied immediately`**: 적용 가능한 업데이트 개수

업데이트 적용(추천):

```bash
sudo apt update
sudo apt upgrade -y
sudo reboot
```

재부팅 후 SSH 재확인:

```bash
sudo systemctl status ssh
sudo ss -tnlp | grep :22
```
