## 📋 문제 2: 소프트웨어 테스트 기법

### 문제
소프트웨어 테스트의 구조 기반(화이트박스) 기법 중 하나로, 결정 포인트(Decision Point) 내에 존재하는 모든 개별 조건식(Atomic Condition) 을 대상으로 하는 커버리지 기준이 있다.

하나의 결정문(예: if (A && B) 또는 if (X > 10 || Y == 0)) 안에는 여러 개의 조건식이 포함될 수 있는데 이 커버리지는 각각의 조건식이 True와 False 두 가지 경우를 모두 한 번 이상 만족하도록 테스트 케이스를 설계해야 한다.

즉, 모든 개별 조건이 두 방향의 결과를 거쳐야 "커버되었다"고 판단하지만 그렇다고 해서 전체 결정식(Decision Expression) 의 결과(True/False)가 모두 수행된다고 보장하지는 않는다.

### 답안
**ㅇ. 조건 (Condition)**

### 해설
- **조건 커버리지(Condition Coverage)**는 결정문 내의 모든 개별 조건식이 True와 False를 각각 한 번 이상 만족하도록 테스트하는 기법입니다.
- 예: `if (A && B)`에서 A와 B가 각각 true, false를 모두 거쳐야 합니다.
- 하지만 전체 결정식의 결과(True/False)가 모두 수행된다는 보장은 없습니다.
- 다른 커버리지:
  - **결정 커버리지**: 전체 결정식의 True/False를 모두 테스트
  - **조건/결정 커버리지**: 조건과 결정을 모두 테스트
  - **MC/DC**: 각 조건이 독립적으로 결정에 영향을 미치는지 테스트

## 📋 문제 4: 오류 검출 방식

### 문제
다음은 오류검출 방식을 설명하는 내용이다. 설명의 빈칸 (①)~(⑤) 에 들어갈 알맞은 용어를 <보기>에서 고르시오.

(①) 코드는 전송 데이터에 여러 개의 검사 비트를 추가하여 오류를 검출하고 수정까지 가능한 방법이다. 이 코드는 재전송 없이 수신 측에서 자체 수정하는 (②) 방식에 속한다.

이에 반해 오류 발생 시 송신 측에 재전송을 요구하는 방식은 (③)이라 하며, 여기에 포함되는 대표적 검출 기법으로 (④) 검사와 (⑤) 검사가 있다.

(④) 검사는 데이터 블록 끝에 1비트 검사 비트를 추가하여 오류를 검출한다.
(⑤) 검사는 송신측과 수신측이 동일한 특정 다항식을 사용하여 오류를 검출한다.

[보기] ㉠ CRC ㉡ FEC ㉢ BEC ㉣ NAK ㉤ Parity ㉥ MD5 ㉦ BCD ㉧ Hamming

### 답안
① **㉧ Hamming**
② **㉡ FEC**
③ **㉢ BEC**
④ **㉤ Parity**
⑤ **㉠ CRC**

### 해설
- **해밍 코드(Hamming Code)**: 오류 검출 및 수정이 가능한 코드, FEC(Forward Error Correction) 방식
- **FEC (Forward Error Correction)**: 재전송 없이 수신 측에서 오류를 자체 수정하는 방식
- **BEC (Backward Error Correction)**: 오류 발생 시 송신 측에 재전송을 요구하는 방식
- **패리티 검사(Parity Check)**: 데이터 블록 끝에 1비트 검사 비트를 추가하여 오류 검출
- **CRC (Cyclic Redundancy Check)**: 다항식을 사용하여 오류를 검출하는 방식

## 📋 문제 5: C 코드 - 구조체 포인터

### 문제
```c
#include <stdio.h>

struct Test {
    int i;
    const char *g;
};

int main() {
    struct Test test[] = {{1, "AB"}, {2, "DC"}, {3, "EB"}}; 
    struct Test *p = &test[1]; 
    printf("%s", p->g + (p->i - 1));
    return 0;
}
```

### 답안
**C**

### 해설
- `test[1]`은 `{2, "DC"}`입니다.
- `p = &test[1]`이므로 `p->i = 2`, `p->g = "DC"`입니다.
- `p->g + (p->i - 1)` = `"DC" + (2 - 1)` = `"DC" + 1` = `"C"`입니다.
- 문자열 포인터에서 `+1`은 다음 문자부터 시작하는 문자열을 가리킵니다.
- 따라서 `"C"`가 출력됩니다.

## 📋 문제 7: C 코드 - 연결 리스트

### 문제
```c
#include <stdio.h>

struct Node {
    struct Node* next;
    unsigned int x;
};

int main() {
    struct Node t1 = { 0, 5u };
    struct Node t2 = { 0, 7u };
    struct Node t3 = { 0, 11u };

    t3.next = &t2;
    t2.next = &t1;

    struct Node* curr = &t3;
    int sum = 0;

    while (curr) {
        sum = sum * 3 + curr->x;
        curr = curr->next;
    }

    sum = (sum ^ 42u) + 100u;

    printf("%u\n", sum);
}
```

### 답안
**187**

### 해설
- 연결 리스트: t3 → t2 → t1 → NULL
- 초기: `sum = 0`
- t3: `sum = 0 * 3 + 11 = 11`
- t2: `sum = 11 * 3 + 7 = 33 + 7 = 40`
- t1: `sum = 40 * 3 + 5 = 120 + 5 = 125`
- `sum = (125 ^ 42) + 100`
- `125 ^ 42` (XOR 연산):
  - 125 = `01111101`
  - 42 = `00101010`
  - XOR = `01110111` = 87
- `sum = 87 + 100 = 187`

```python
data = [
    [3, 5, 2, 4, 1],
```

## 📋 문제 15: C 코드 - 연산자

### 문제
```c
#include <stdio.h>
int main() {
    int x=7, y=4, z;
    z = y%3<3 ? 2 : 1;
    z = z & z >> 1;
    z = x>5 && z<=3 ? z*x : z/x;
    printf("%d", z);
    return 0;
}
```

### 답안
**0**

### 해설
1. `z = y%3<3 ? 2 : 1`
   - `y%3 = 4%3 = 1`
   - `1<3` → true
   - `z = 2`

2. `z = z & z >> 1`
   - `z >> 1 = 2 >> 1 = 1` (비트 시프트)
   - `z & 1 = 2 & 1`
   - `2 = 0010`, `1 = 0001`
   - `0010 & 0001 = 0000 = 0`
   - `z = 0`

3. `z = x>5 && z<=3 ? z*x : z/x`
   - `x>5 = 7>5` → true
   - `z<=3 = 0<=3` → true
   - `true && true` → true
   - `z*x = 0*7 = 0`
   - `z = 0`

ㄴ. 실제 데이터가 저장되어 있는 테이블의 내용 전체를 의미하며, 데이터의 상태를 나타낸다.
ㄷ. 테이블에 저장된 행(Row)의 총 개수를 의미한다.

[보기] 스키마(Structure) 속성(Attribute) 튜플(Tuple) 차수(Degree) 인스턴스(Instance) 카디널리티(Cardinality)

### 답안
ㄱ. **튜플(Tuple)**
ㄴ. **인스턴스(Instance)**
ㄷ. **카디널리티(Cardinality)**

### 해설
- **튜플(Tuple)**: 테이블의 한 행, 레코드를 구성하는 요소

- **속성(Attribute)**: 테이블의 열(Column)
- **차수(Degree)**: 속성의 개수
- **스키마(Structure)**: 데이터베이스의 구조

## 📋 문제 17: Java Enum

### 문제
```java
enum Tri {
    A("A"), B("AB"), C("ABC");

    private String code;

    Tri(String code) {
        this.code = code;
    }

    public String code() {
        return code;
    }
}

public class Main {
    public static void main(String[] args) {
        Tri t = Tri.values()[Tri.A.name().length()];
        System.out.print(t.code());
    }
}
```

### 답안
**AB**

### 해설
- `Tri.A.name()` = `"A"` (문자열 길이 1)
- `Tri.A.name().length()` = `1`
- `Tri.values()[1]` = `Tri.B`
- `Tri.B.code()` = `"AB"`

## 📋 문제 18: 접근통제 모델

### 문제
다음은 정보보안에서 사용하는 접근통제(Access Control) 방식에 대한 설명이다. 설명에 해당하는 접근통제 모델을 <보기>에서 골라 빈칸에 작성하시오.

ㄱ. 중앙에서 보안 정책을 일괄적으로 설정하며, 주체(사용자)가 임의로 수정하거나 변경할 수 없다. 주로 군사 기밀, 국가 보안과 같은 높은 보안 수준이 요구되는 환경에서 사용된다. 보안 등급(Top Secret / Secret / Confidential 등)에 따라 접근 여부가 결정된다.

ㄴ. 조직 내에서 부여된 직무나 역할(Role)에 따라 접근 권한을 부여하는 방식이다. 개별 사용자에게 직접 권한을 설정하지 않고, 역할에 권한을 묶어 부여하기 때문에 관리가 용이하며 직무 변경 시 역할만 변경하면 된다.

ㄷ. 자원의 소유자(Owner)가 해당 자원에 대한 접근 권한을 자유롭게 부여하거나 회수할 수 있는 방식이다. 파일이나 폴더의 소유자가 읽기/쓰기/실행 권한을 설정하는 것이 대표적인 예로 사용자의 임의 설정이 가능해 보안성이 상대적으로 낮다.

[보기] DAC MAC RBAC

### 답안
ㄱ. **MAC**
ㄴ. **RBAC**
ㄷ. **DAC**

### 해설
- **MAC (Mandatory Access Control)**: 강제 접근 통제
  - 중앙에서 정책 설정, 사용자 임의 변경 불가
  - 보안 등급에 따른 접근 제어
  - 군사, 국가 보안 등 고보안 환경

- **RBAC (Role-Based Access Control)**: 역할 기반 접근 통제
  - 역할(Role)에 권한 부여
  - 사용자에게 역할 할당
  - 관리 용이, 직무 변경 시 역할만 변경

- **DAC (Discretionary Access Control)**: 임의 접근 통제
  - 소유자가 권한 부여/회수
  - 파일/폴더 권한 설정
  - 사용자 임의 설정 가능, 보안성 상대적으로 낮음

## 📋 문제 20: SQL COUNT

### 문제
다음은 SQL에 관한 문제이다. 아래 A테이블을 참고하여 쿼리의 결과를 작성하시오.

**SQL:**
```sql
SELECT count(col2) FROM A WHERE col1 IN (2, 3) OR col2 IN (3, 5)
```

### 답안
**4**

### 해설
- `WHERE col1 IN (2, 3) OR col2 IN (3, 5)` 조건을 만족하는 행을 찾습니다.
- `col1 IN (2, 3)`: col1이 2 또는 3인 행
- `col2 IN (3, 5)`: col2가 3 또는 5인 행
- OR 조건이므로 둘 중 하나만 만족하면 됩니다.
- `count(col2)`는 `col2`가 NULL이 아닌 행의 개수를 세는 함수입니다.
- 조건을 만족하는 행 중 `col2`가 NULL이 아닌 행의 개수는 **4**입니다.
