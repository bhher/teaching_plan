```java
package a0825.shop;

public class MemberDiscount implements Discount {
    @Override
    public double apply(int price) {
        return (int) (price * 0.9);
    }

    @Override
    public String getName() {
        return "회원할인";
    }
}
```

```java
package a0825.shop;

public class CouponDiscount implements Discount {
    private int couponAmount;

    public CouponDiscount(int couponAmount) {
        this.couponAmount = couponAmount;
    }

    @Override
    public double apply(int price) {
        int result = price - couponAmount;
        return result < 0 ? 0 : result;
    }

    @Override
    public String getName() {
        return "쿠폰할인(" + couponAmount + "원)";
    }
}
```

## 결제 구현

```java
package a0825.shop;

public class CardPay implements Payable {
    private int limit;

    public CardPay(int limit) {
        this.limit = limit;
    }

    @Override
    public boolean pay(int amount) {
        if (amount > limit) {
            System.out.println("잔액(한도) 부족");
            return false;
        }
        limit -= amount;
        System.out.println("카드 결제 완료: " + amount + "원");
        return true;
    }

    @Override
    public String getMethodName() {
        return "카드";
    }
}
```

```java
package a0825.shop;

public class KakaoPay implements Payable {
    private int balance;

    public KakaoPay(int balance) {

        System.out.println("카카오페이 결제 완료: " + amount + "원");
```

## OrderService.java

```java
package a0825.shop;

public class OrderService {
    private Discount discount;
    private Payable payable;
    private Notifier notifier;

    public OrderService(Discount discount, Payable payable, Notifier notifier) {
        this.discount = discount;
        this.payable = payable;
        this.notifier = notifier;
    }

    public boolean checkout(String productName, int price) {
        System.out.println("상품: " + productName + " | 원가: " + price + "원");
        System.out.println("적용 할인: " + discount.getName());

        int payAmount = (int) discount.apply(price);
        System.out.println("결제 금액: " + payAmount + "원");

        boolean ok = payable.pay(payAmount);
        if (ok) {
            notifier.send(productName + " 결제 완료 (" + payAmount + "원)");
            System.out.println("주문 성공!");
        } else {
            System.out.println("주문 실패");
        }
        return ok;
    }
}
```

```java
public class ShopMain {

        System.out.println("===== 주문 1 =====");
        OrderService order1 = new OrderService(
                new MemberDiscount(),

                new SmsNotifier()

        OrderService order3 = new OrderService(
                new NoDiscount(),
                new BankTransfer(),
                new SmsNotifier()
        );
        order3.checkout("마우스", 20000);
    }
}
```

## (선택) 여러 알림 동시 발송

```java
import java.util.ArrayList;
import java.util.List;

public class MultiNotifier implements Notifier {
    private List<Notifier> list = new ArrayList<>();

    public void add(Notifier n) {
        list.add(n);
    }

    @Override
    public void send(String message) {
        for (Notifier n : list) {
            n.send(message);
        }
    }
}

// 사용
MultiNotifier multi = new MultiNotifier();
multi.add(new SmsNotifier());
multi.add(new EmailNotifier());
OrderService order = new OrderService(new NoDiscount(), new BankTransfer(), multi);
```

## 설계 포인트 (요약)

| 원칙 | 이 코드에서 |
|------|-------------|
| 인터페이스로 역할 분리 | 할인 / 결제 / 알림 |
| 의존성 주입 | 생성자로 구현체 전달 |
| 다형성 | `discount.apply`, `payable.pay` — 구현 몰라도 동작 |
| 교체 용이 | 카드 → 계좌이체만 바꿔도 OrderService 수정 없음 |

```text
OrderService는 "카드"를 모른다.
오직 Payable 만 안다.  →  실무 서비스 계층과 같은 패턴
```

# 상세 해설 (수업용)

코드만 보고 넘어가기 쉬운 부분을, **왜 이렇게 설계했는지**까지 풀어 설명합니다.

---

## 1. 전체 구조부터 이해하기

쇼핑몰에는 크게 **3가지 역할**이 있습니다.

| 역할 | 인터페이스 |
|------|------------|
| 할인 | `Discount` |
| 결제 | `Payable` |
| 알림 | `Notifier` |

이 셋을 사용하는 **주문 담당자**가 `OrderService`입니다.

```text
                  ┌─────────────────┐
                  │   OrderService  │
                  │  Discount       │
                  │  Payable        │
                  │  Notifier       │
                  └───────┬─────────┘
                          │
             ┌────────────┼────────────┐
             ↓            ↓            ↓
         할인 기능      결제 기능      알림 기능
             │            │            │
       ┌─────┼─────┐  ┌───┼──────┐  ┌──┴─────┐
       ↓     ↓     ↓  ↓   ↓      ↓  ↓        ↓
     No   Member Coupon Card Kakao Bank SMS  Email
```

핵심: **`OrderService`는 구현 클래스 이름을 몰라도 된다.**  
인터페이스만 알면 된다.

---

## 2. Discount 인터페이스

```java
public interface Discount {
    double apply(int price);  // 원가 → 할인 후 금액
    String getName();         // "회원할인" 등
}
```

계약: *“할인 기능을 만들려면 `apply()`와 `getName()`을 제공해야 한다.”*

```text
100,000원 → 회원 할인 → 90,000원
```

## 5. CouponDiscount

생성자로 쿠폰 금액을 받습니다. (`new CouponDiscount(5000)`)

```java
int result = price - couponAmount;
return result < 0 ? 0 : result;
```

삼항 연산자: `result < 0` 이면 **0**, 아니면 `result`.  
상품 3,000원 · 쿠폰 5,000원이면 음수가 되므로 **0원**으로 막습니다.

---

## 6. Payable 인터페이스

```java
public interface Payable {
    boolean pay(int amount);  // 성공 true / 실패 false
    String getMethodName();
}
```

카드 · 카카오페이 · 계좌이체 **모두** `pay()`로 결제할 수 있어야 합니다.

## 7. CardPay

- `private int limit` — 카드 한도 (`new CardPay(200000)`)
- `amount > limit` → `"잔액(한도) 부족"`, `false`
- 아니면 `limit -= amount`, `true`

## 8. KakaoPay

구조는 카드와 같고, 필드는 `balance`(잔액).  
**인터페이스는 같고 구현만 다름 → 다형성.**

## 9. BankTransfer

실무라면 계좌 확인 등이 들어갑니다.

## 15. 생성자 주입 (DI) ⭐

```java
public OrderService(Discount discount, Payable payable, Notifier notifier) {
    this.discount = discount;
    this.payable = payable;
    this.notifier = notifier;
}
```

```java
new OrderService(
    new MemberDiscount(),

    new SmsNotifier()

```

외부에서 객체를 넣어 주는 것을 **의존성 주입(Dependency Injection)** 이라고 합니다.

## 16~20. checkout() 실행 과정

```java
order1.checkout("무선이어폰", 100000);
```

| 단계 | 코드 | 의미 |
|------|------|------|
| ① | 상품·원가 출력 | 정보 표시 |
| ② | `discount.getName()` / `discount.apply(price)` | 실제로는 `MemberDiscount` 메서드 |
| ③ | `payable.pay(payAmount)` | 실제로는 `CardPay.pay(...)` |
| ④ | 성공 시 `notifier.send(...)` | 실제로는 SMS 또는 EMAIL |

```text
코드는 payable.pay(payAmount); 한 줄뿐
 → OrderService는 카드/카카오/계좌를 몰라도 됨
 → 실제 객체에 따라 다른 pay()가 실행됨  (= 다형성)
```

결제 실패(`ok == false`)면 알림을 보내지 않습니다.

## 21~24. 주문 1 · 2 · 3 분석

### 주문 1 — 성공

```text
MemberDiscount + CardPay(200000) + SmsNotifier
100,000 → 회원할인 → 90,000 → 카드 결제 성공 → SMS → 주문 성공
```

```text
CouponDiscount(5000) + KakaoPay(30000) + EmailNotifier
50,000 → 쿠폰 → 45,000 → 잔액 30,000 → 실패 (알림 없음)
```

### 주문 3 — 성공

```text
NoDiscount + BankTransfer + SmsNotifier
20,000 → 할인없음 → 계좌이체 → SMS → 주문 성공
```

**구현체만 바뀌고 `OrderService` 코드는 수정하지 않음** → 이 예제의 핵심.

## 25~27. 인터페이스가 없으면? / 느슨한 결합

인터페이스 없이:

```java
private MemberDiscount discount;
private CardPay payable;
```

카카오페이로 바꾸려면 필드를 `KakaoPay`로 **고치고** OrderService를 수정해야 합니다.  
→ **강한 결합**.

인터페이스로:

```java
private Discount discount;
private Payable payable;
private Notifier notifier;
```

```text
             OrderService
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
   Discount    Payable    Notifier
       ↑          ↑          ↑
      구현체      구현체      구현체
```

*“어떻게 하는지는 모르겠고, **무엇을 할 수 있는지만** 알겠다.”* → **느슨한 결합**.

## 29~30. (선택) MultiNotifier

`MultiNotifier`도 `Notifier`입니다. 안에 `List<Notifier>`를 두고 SMS·EMAIL을 여러 개 등록합니다.

```java
@Override
public void send(String message) {
    for (Notifier n : list) {
        n.send(message);  // 등록된 알림 전부
    }
}
```

```text
multi.send("주문 완료") → SMS + EMAIL 둘 다
```

역시 인터페이스 다형성입니다.

---

## 31. 핵심 4가지 (반드시 강조)

1. **역할 분리** — Discount / Payable / Notifier  
2. **다형성** — `Payable` 하나로 Card·Kakao·Bank  
3. **생성자 의존성 주입** — 밖에서 구현체 전달  
4. **구현체 교체** — `CardPay` → `KakaoPay` 해도 OrderService 수정 없음  

---

## 32. 학생용 한 줄 요약

> OrderService는 할인·결제·알림을 직접 만들지 않고 **인터페이스로만** 사용한다.  
> 어떤 할인·결제·알림인지는 몰라도 되고, **외부에서 주입한 구현체**의 메서드가 실행된다.  
> 이것이 인터페이스 다형성과 의존성 주입의 기본 형태이며, Spring으로 자연스럽게 이어진다.
