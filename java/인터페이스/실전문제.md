# 인터페이스 실전 문제 — 온라인 쇼핑몰 주문 시스템

인터페이스로 **결제 · 할인 · 알림**을 분리한 실무형 연습입니다.  
기본 개념은 [문제.md](./문제.md)를 먼저 풀어 보세요.

정답: [실전정답.md](./실전정답.md)

---

## 시나리오

고객이 상품을 담고 결제하면:

1. **할인** 적용 (회원 / 쿠폰 / 없음)
2. **결제** 수단으로 지불 (카드 / 카카오페이 / 계좌이체)
3. **알림** 발송 (문자 / 이메일)

결제·할인·알림 방식을 바꿔도 **주문 처리 코드는 거의 안 바뀌게** 인터페이스로 설계하세요.

```text
        OrderService (주문 처리)
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
 Discount  Payable  Notifier
 (할인)    (결제)    (알림)
    │         │         │
 구현체들   구현체들   구현체들
```

## 구현할 타입

### 1. 인터페이스 3개

#### `Discount`

```java
double apply(int price);  // 원가 → 할인 후 금액 반환
String getName();         // 할인 이름 (출력용)
```

#### `Payable`

```java
boolean pay(int amount);  // 결제 시도, 성공 true / 실패 false
String getMethodName();   // "카드", "카카오페이" 등
```

#### `Notifier`

```java
void send(String message);  // 알림 발송
```

---

### 2. 할인 구현 클래스

| 클래스 | 동작 |
|--------|------|
| `NoDiscount` | 할인 없음, 원가 그대로 |
| `MemberDiscount` | **10%** 할인 (원가 × 0.9, 원 단위 버림 `(int)`) |
| `CouponDiscount` | 생성자로 `int couponAmount` — 정액 할인. 결과가 0 미만이면 **0** |

---

### 3. 결제 구현 클래스

| 클래스 | 동작 |
|--------|------|
| `CardPay` | 잔액(한도) 필드. 금액 ≤ 한도면 차감 후 `"카드 결제 완료: ○○원"` , true |
| `KakaoPay` | 잔액 필드. 동일 로직, 메시지만 `"카카오페이 결제 완료: ○○원"` |
| `BankTransfer` | 잔액 없이 **항상 성공**. `"계좌이체 완료: ○○원"` |

잔액 부족 시: `"잔액(한도) 부족"` 출력 후 `false`

---

### 4. 알림 구현 클래스

| 클래스 | 출력 예 |
|--------|---------|
| `SmsNotifier` | `[SMS] 주문하신 상품 결제가 완료되었습니다` |
| `EmailNotifier` | `[EMAIL] 주문하신 상품 결제가 완료되었습니다` |

(`send`에 넘어온 `message`를 그대로 뒤에 붙이거나, 위 형식으로 감싸도 됨)

---

### 5. `OrderService` 클래스

```java
public class OrderService {
    private Discount discount;
    private Payable payable;
    private Notifier notifier;

    public OrderService(Discount discount, Payable payable, Notifier notifier) {
        // 저장
    }

    /**
     * 1) 할인 적용
     * 2) 결제
     * 3) 성공 시에만 알림
     * @return 결제 성공 여부
     */
    public boolean checkout(String productName, int price) { ... }
}
```

`checkout` 처리 순서와 출력 예:

```text
상품: 무선이어폰 | 원가: 100000원
적용 할인: 회원할인
결제 금액: 90000원
카드 결제 완료: 90000원
[SMS] 무선이어폰 결제 완료 (90000원)
주문 성공!
```

결제 실패 시:

```text
...
잔액(한도) 부족
주문 실패
```

(알림은 **보내지 않음**)

---

### 6. `ShopMain` (실행)

더미로 **서로 다른 조합 3번** `checkout` 호출:

| # | 상품 | 원가 | 할인 | 결제 | 알림 |
|---|------|------|------|------|------|
| 1 | 무선이어폰 | 100000 | 회원 10% | 카드(한도 200000) | SMS |
| 2 | 키보드 | 50000 | 쿠폰 5000원 | 카카오페이(잔액 30000) | EMAIL — **실패 예상** |
| 3 | 마우스 | 20000 | 할인 없음 | 계좌이체 | SMS |

---

## 필수 요구사항

1. 결제·할인·알림은 **반드시 인터페이스**로만 `OrderService`에 주입 (`new CardPay`를 OrderService 안에 하드코딩하지 말 것)
2. `checkout` 안에서 구현 클래스 이름을 `if`로 나누지 말 것 — **인터페이스 메서드만** 호출
3. 금액은 `int` (원), 할인 시 소수점은 `(int)` 로 버림
4. 입력 `Scanner` 없어도 됨 (더미 데이터로 충분)

## 채점 포인트

| 항목 | 내용 |
|------|------|
| 인터페이스 분리 | Discount / Payable / Notifier |
| 다형성 | OrderService가 구현체에 의존하지 않음 |
| 조합 | 생성자로 다른 구현 교체 가능 |
| 실패 처리 | 결제 실패 시 알림 스킵 |
| 동작 | 더미 3건 결과가 예시와 논리적으로 같음 |

---

## 도전 (선택)

1. **`Discount` 체인**: 회원할인 후 쿠폰 추가 적용 (인터페이스 배열 또는 리스트)
2. **여러 Notifier**: SMS + EMAIL 동시 발송 (`List<Notifier>`)
3. **`Payable`에 `default` 메서드**: `default void printReceipt(int amount) { ... }`

## 왜 인터페이스인가? (수업용 한 줄)

> 카드 → 카카오페이로 바꿔도 `OrderService.checkout` 코드는 그대로.  
> **변하는 부분만 구현 클래스**, **공통 약속은 인터페이스**.
