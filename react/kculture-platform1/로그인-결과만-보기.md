# 로그인 결과만 보려면 (서버·클라이언트에 쓰는 것)

**목표:** 로그인 요청 후 **응답 JSON**만 확인하고 싶을 때, 서버와 클라이언트에 각각 무엇이 필요한지 정리합니다.  
(실제 프로젝트는 이미 `server/index.js`, `client/src/api/client.js`, `AuthContext`, `LoginPage`에 구현되어 있습니다.)

---

## 1. 서버(Express)에서 필요한 것

### 1) 로그인 성공 시 내려주는 형태

성공 시 본문은 대략 다음과 같습니다.

```json
{
  "member": {
    "id": 1,
    "email": "tourist@test.com",
    "name": "John",
    "nationality": "USA",
    "language": "en"
  }
}
```

비밀번호는 **절대** 넣지 않습니다.

### 2) 이 프로젝트에서 해당 역할을 하는 코드 위치

| 내용 | 파일·위치 |
|------|-----------|
| 로그인 처리 | `server/index.js` — `POST /api/auth/login` |
| 세션에 회원 ID 저장 | 같은 핸들러 안 `req.session.memberId = row.id` |
| 회원 정보 매핑(비번 제외) | `mapMemberRow(row)` |
| JSON 파싱 | `app.use(express.json())` (상단 미들웨어) |
| 쿠키로 세션 유지 | `express-session` + 쿠키 이름 `kculture1.sid` |
| 다른 포트의 React에서 호출 허용 | `cors({ origin: CLIENT_ORIGIN, credentials: true })` |

### 3) “최소”로 로그인 API만 쓰는 서버 예시 (개념)

DB 없이 **고정 계정만** 통과시키는 테스트용이라면 예를 들어:

```js
app.post('/api/auth/login', (req, res) => {
  const { email, password } = req.body;
  if (email === 'test@test.com' && password === '1234') {
    req.session.memberId = 1;
    res.json({
      member: { id: 1, email: 'test@test.com', name: '테스트', nationality: null, language: 'en' },
    });
    return;
  }
  res.status(401).json({ error: 'Invalid email or password.' });
});
```

**이 프로젝트(kculture-platform1)** 는 MySQL의 `member` 테이블로 조회하므로, **`pool.query`** 와 `mapMemberRow` 가 들어 있는 현재 `index.js` 구현을 그대로 쓰면 됩니다.

---

## 2. 클라이언트(React)에서 필요한 것

### 1) 반드시 넣을 것: `credentials: 'include'`

세션 쿠키를 주고받으려면 `fetch`에 다음이 필요합니다.

```js
fetch('/api/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email, password }),
  credentials: 'include',
});
```

그다음 `res.json()`으로 위의 `{ member: { ... } }` 를 받습니다.

### 2) 이 프로젝트에서 해당 역할을 하는 파일

| 내용 | 파일 |
|------|------|
| 위 `fetch` 래핑 | `client/src/api/client.js` — `api.login({ email, password })` |
| 로그인 후 상태에 `member` 저장 | `client/src/context/AuthContext.jsx` — `login()` 안에서 `setMember(m)` |
| 화면(폼·에러 표시) | `client/src/pages/LoginPage.jsx` |

### 3) “결과만” 화면에 찍어 보기 (예시)

`LoginPage`의 `submit` 안에서 **네비게이트 전에** 잠깐 로그를 찍는 방법:

```js
const submit = async (e) => {
  e.preventDefault();
  try {
    const data = await api.login({ email, password });
    console.log('로그인 응답:', data);
    // { member: { id, email, name, ... } }
    navigate(from, { replace: true });
  } catch (err) {
    console.log('로그인 실패:', err.data ?? err.message);
  }
};
```

또는 **페이지만 따로** 만들어서:

```jsx
const [result, setResult] = useState(null);
const tryLogin = async () => {
  const res = await fetch('/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
    credentials: 'include',
  });
  const data = await res.json();
  setResult(JSON.stringify(data, null, 2));
};
// return <pre>{result}</pre>;
```

### 4) Vite 개발 서버

`client/vite.config.js`에서 `/api`를 Express(예: `http://localhost:3002`)로 **프록시**해 두어야, 브라우저가 `http://localhost:5173/api/...` 로 요청해도 백엔드로 전달됩니다. 이 프로젝트에는 이미 설정되어 있습니다.

---

## 3. 체크리스트

| 항목 | 서버 | 클라이언트 |
|------|------|------------|
| 로그인 URL | `POST /api/auth/login` | 같은 경로로 `fetch` |
| JSON 본문 | `req.body.email`, `req.body.password` | `JSON.stringify({ email, password })` |
| 세션 쿠키 | `express-session` | `credentials: 'include'` |
| 실패 시 | `401` + `{ error: "..." }` | `catch` 또는 `res.ok` 확인 |

---

## 4. 한 줄 요약

- **서버:** `POST /api/auth/login`에서 DB(또는 테스트 계정) 검증 후 **`res.json({ member: { ... } })`**  
- **클라이언트:** **`fetch` + `credentials: 'include'`** 로 호출한 뒤 **`res.json()`** 결과를 `console.log` 또는 `useState`로 보면 됩니다.

이 저장소에서는 별도 파일을 새로 만들 필요 없이, 위 경로의 **`index.js`**, **`client.js`**, **`AuthContext.jsx`**, **`LoginPage.jsx`** 를 참고하면 됩니다.
