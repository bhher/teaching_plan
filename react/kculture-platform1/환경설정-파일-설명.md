# 환경 설정 파일 설명 (`kculture-platform1`)

`.env.example`, `db.js`, `env.js`, `.env` 가 **설치 시 자동 생성되는지**, **각각 무엇을 하는지** 정리합니다.

---

## `npm install`으로 자동으로 생기나요?

| 대상 | 자동 생성? | 설명 |
|------|------------|------|
| **`node_modules/`** | 예 | `npm install` 할 때만 생성됩니다. |
| **`.env.example`** | 아니요 | 저장소에 **이미 포함**된 파일입니다. 클론/복사하면 함께 옵니다. |
| **`.env`** | 아니요 | **직접 만듭니다.** 보통 `.env.example`을 복사해 이름을 `.env`로 바꾼 뒤 값을 채웁니다. |
| **`db.js`** | 아니요 | 프로젝트 **소스 코드**입니다. 저장소에 포함되어 있습니다. |
| **`env.js`** | 아니요 | 마찬가지로 **소스 코드**입니다. |

**정리:** `npm install`은 **의존성(`node_modules`)만** 만들고, `.env`나 DB 설정용 파일을 **자동으로 만들어 주지 않습니다.**  
`.env`는 비밀번호 등이 들어가므로 Git에 올리지 않는 경우가 많아, **예시만 `.env.example`에 두고** 사용자가 `.env`를 직접 만드는 방식이 일반적입니다.

---

## 각 파일의 역할

### `.env.example`

- **역할:** `.env`에 넣어야 할 **변수 이름·형식**을 보여 주는 **템플릿**입니다.
- **예:** `PORT`, `MYSQL_PASSWORD`, `SESSION_SECRET`, `CLIENT_ORIGIN` 등.
- 비밀값 없이 Git에 올려도 되는 **샘플**입니다.

### `.env` (사용자가 만드는 파일)

- **역할:** **실제 비밀번호·시크릿** 등을 적는 파일입니다. 서버 실행 시 이 값을 읽습니다.
- **`env.js`**, **`db.js`** 가 이 파일을 참조합니다.
- 보통 **`.gitignore`에 등록**해 저장소에 포함하지 않습니다.
- 클론만 하고 `.env`를 만들지 않으면 DB 비밀번호가 비어 있어 **접속 오류**가 날 수 있습니다.

### `env.js`

- **역할:** `dotenv`로 **`server` 폴더 기준 `.env` 파일 경로**를 지정해 로드합니다.
- 터미널 **현재 작업 폴더(cwd)** 가 어디든 **`server/.env`를 찾도록** 하기 위한 모듈입니다.
- `index.js` 맨 위에서 `import './env.js'` 로 가장 먼저 불러옵니다.

### `db.js`

- **역할:** **MySQL 연결 풀**(`mysql2`)을 만들고 `export` 합니다.
- `.env`의 `MYSQL_HOST`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE` 등으로 연결을 설정합니다.
- 이 프로젝트에서는 **`db.js` 안에서도 `dotenv`로 `server/.env`를 로드**해, 모듈 로드 순서와 관계없이 환경 변수가 적용되도록 해 두었습니다.

---

## 처음 세팅할 때 할 일

1. `server` 폴더에서 **`.env.example`을 복사**해 **`.env`** 로 저장합니다.
2. `.env` 안의 `MYSQL_PASSWORD`, `SESSION_SECRET` 등을 **본인 PC·MySQL에 맞게** 수정합니다.
3. `server`와 `client`에서 각각 `npm install`을 실행합니다.

저장소에 이미 `db.js`, `env.js`, `.env.example`이 있다면 **새로 작성할 필요는 없고**, **`.env`만 복사·편집**하면 됩니다.
