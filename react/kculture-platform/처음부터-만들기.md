# K-Culture Platform — 처음부터 만드는 과정

이 문서는 **폴더 생성부터** 이 프로젝트와 같은 구조(**Vite + React Router + Express + MySQL + 세션 쿠키**)를 갖추는 흐름을 정리한 것입니다. 이미 이 저장소에 예제가 있다면, **참고용 체크리스트**로 쓰면 됩니다.

---

## 1. 필요한 프로그램

| 프로그램 | 용도 | 비고 |
|----------|------|------|
| **Node.js** (LTS 권장) | JavaScript 실행, `npm` 포함 | [https://nodejs.org](https://nodejs.org) |
| **npm** | 패키지 설치·스크립트 실행 | Node 설치 시 함께 설치됨 |
| **MySQL** (또는 MariaDB) | 게시글·회원·댓글 DB | 설치 후 서비스 기동 확인 |
| **코드 편집기** | VS Code, Cursor 등 | 선택 |
| **Git** (선택) | 버전 관리 | 없어도 로컬 개발은 가능 |

터미널에서 버전 확인:

```bash
node -v
npm -v
```

MySQL은 설치 환경에 따라 `mysql -V` 또는 Workbench로 접속 테스트를 합니다.

---

## 2. 최상위 폴더 만들기

원하는 위치에 프로젝트 루트 폴더를 만듭니다. 예:

```text
kculture-platform/
├── client/     ← React (Vite) 프론트엔드
└── server/     ← Express API + 세션 + DB
```

### Windows (PowerShell 예시)

```powershell
mkdir kculture-platform
cd kculture-platform
mkdir client, server
```

---

## 3. 서버(`server`) — Express API

### 3.1 초기화

```powershell
cd server
npm init -y
```

### 3.2 패키지 설치

```powershell
npm install express cors express-session mysql2 dotenv
```

개발 시 서버 파일 변경 감지(선택):

```powershell
npm pkg set scripts.dev="node --watch index.js"
npm pkg set scripts.start="node index.js"
```

### 3.3 만들 파일(개념)

| 파일 | 역할 |
|------|------|
| `env.js` | `server` 폴더 기준으로 `.env` 로드 (실행 위치와 무관하게 동작) |
| `db.js` | `mysql2` 연결 풀 |
| `index.js` | 라우트: `/api/categories`, `/api/posts`, `/api/auth/*` 등 |
| `.env` | 포트, MySQL 계정, `SESSION_SECRET`, `CLIENT_ORIGIN` |
| `.env.example` | `.env` 템플릿 (비밀값 없이 커밋 가능) |

### 3.4 환경 변수

`.env` 예시 항목:

- `PORT` — API 포트 (예: `3001`)
- `CLIENT_ORIGIN` — 브라우저 주소 (예: `http://localhost:5173`)
- `SESSION_SECRET` — 세션 암호화용 긴 문자열
- `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE`

### 3.5 세션·CORS

- 로그인 후 **세션 ID**를 **httpOnly 쿠키**로 저장 (`express-session`).
- 프론트는 `fetch(..., { credentials: 'include' })`로 쿠키 전송.
- 브라우저 출처와 API가 다르면 **CORS**에서 `credentials: true`와 허용 `origin` 설정.

## 4. 클라이언트(`client`) — Vite + React

### 4.1 Vite로 React 프로젝트 생성

`client` 폴더가 비어 있으면, **부모 폴더에서** 한 번에 만들 수도 있습니다.

```powershell
cd ..
npm create vite@latest client -- --template react
cd client
npm install
```

### 4.2 React Router 설치

```powershell
npm install react-router-dom
```

### 4.3 만들 폴더·파일(개념)

```text
client/
├── index.html
├── vite.config.js
└── src/
    ├── main.jsx          ← BrowserRouter, Provider
    ├── App.jsx           ← Routes 정의
    ├── index.css
    ├── api/
    │   └── client.js     ← fetch + credentials: 'include'
    ├── components/
    │   └── Layout.jsx
    ├── context/
    │   └── AuthContext.jsx
    └── pages/
        ├── HomePage.jsx
        ├── PostPage.jsx
        ├── WritePage.jsx
        ├── EditPage.jsx
        ├── LoginPage.jsx
        └── JoinPage.jsx
```

### 4.4 Vite 개발 서버 프록시

`vite.config.js`에 `server.proxy`로 `/api` → `http://localhost:3001`을 연결하면, 개발 중 브라우저는 `http://localhost:5173/api/...`로 호출해 **같은 출처처럼** 쿠키를 쓰기 쉽습니다.

### 4.5 라우트와 JSP URL 대응(예시)

| 기존 JSP | React Router |
|----------|----------------|
| `list.do` | `/` |
| `view.do?id=` | `/posts/:id` |
| `write.do` | `/write` |
| `edit.do` | `/posts/:id/edit` |
| 로그인·가입 | `/login`, `/join` |

## 5. 데이터베이스

1. MySQL에 스키마 적용 (이 저장소에서는 `jsp/예제/17-Kculture-Platform/schema.sql`).
2. `member`, `category`, `post`, `comment` 테이블이 생성되는지 확인.
3. API의 `MYSQL_DATABASE`와 스키마 이름이 일치하는지 확인.

---

## 6. 실행 순서 (매번)

1. MySQL 서버 실행.
2. **터미널 1** — `server`에서 `npm run dev` (또는 `npm start`).
3. **터미널 2** — `client`에서 `npm run dev`.
4. 브라우저에서 Vite 주소(보통 `http://localhost:5173`) 접속.
5. Vite가 **5173이 아닌 포트**를 쓰면, `server/.env`의 `CLIENT_ORIGIN`을 그 주소로 맞춤.

---

## 7. 빌드(`dist`)란?

```powershell
cd client
npm run build
```

`client/dist/`에 정적 파일이 생성됩니다. `index.html`과 `assets/`의 JS·CSS가 **배포용** 결과입니다. 운영 환경에서는 이 폴더를 Nginx 등으로 서빙하고, API는 별도 도메인 또는 같은 도메인의 `/api` 프록시로 맞춥니다.
