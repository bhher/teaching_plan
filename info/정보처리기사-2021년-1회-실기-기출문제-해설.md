## 문제 1. RARP (Reverse Address Resolution Protocol)

### 문제
물리 네트워크(MAC) 주소에 해당하는 IP 주소를 알려주는 프로토콜로 역순 주소 결정 프로토콜을 무엇이라고 하는지 쓰시오.

### 정답
**RARP (Reverse Address Resolution Protocol)**

### 해설
**ARP vs RARP:**

| 프로토콜 | 설명 | 방향 |
|---------|------|------|
| **ARP** | IP 주소 → MAC 주소 | 정방향 |
| **RARP** | MAC 주소 → IP 주소 | 역방향 |

**RARP 동작 과정:**

```
[클라이언트]                    [RARP 서버]
MAC: 00:11:22:33:44:55
    │
    ├─ RARP 요청 (MAC 주소) ───→│
    │                           │
    │←── IP 주소 할당 ───────────┤
    │                           │
IP: 192.168.1.100
```

**OSI 7계층 프로토콜 분류:**

| 계층 | 이름 | 주요 프로토콜 |
|------|------|-------------|
| 1계층 | 물리 계층 | 전선, 전파, 광섬유, 동축케이블, 모뎀 |
| 2계층 | 데이터 링크 계층 | Ethernet, Token Ring, PPP, HDLC, ATM |
| 3계층 | 네트워크 계층 | **IP, ARP, RARP**, ICMP, IGMP, 라우팅 프로토콜 |
| 4계층 | 전송 계층 | TCP, UDP, RTP, SCTP, SPX |
| 5계층 | 세션 계층 | TLS, SSH, RPC, NetBIOS |
| 6계층 | 표현 계층 | JPEG, MPEG, XDR, ASN.1, SMB |
| 7계층 | 응용 계층 | HTTP, SMTP, SNMP, FTP, Telnet, SSH |

**RARP 특징:**
- MAC 주소를 알고 있을 때 IP 주소를 요청
- 디스크 없는 워크스테이션에서 사용
- 현재는 DHCP로 대체됨

### 정답
**WSDL (Web Services Description Language)**

### 해설
**WSDL 특징:**

| 특징 | 설명 |
|------|------|
| **형식** | XML 형식 |
| **목적** | 웹 서비스 기술 언어 |
| **내용** | 서비스 제공 위치, 메시지 포맷, 프로토콜 |

**WSDL 구성 요소:**

| 구성 요소 | 설명 |

## 문제 6. SQL 논리연산자 우선순위

### 문제
**급여 테이블:**
| EMPNO | SAL |
|-------|-----|
| 100 | 1000 |
| 200 | 3000 |
| 300 | 1500 |

**쿼리:**
```sql
SELECT COUNT(*) FROM 급여
WHERE EMPNO > 100 AND SAL >= 3000 OR EMPNO = 200;
```

### 정답
**1**

### 해설
**논리연산자 우선순위:**
- `AND`가 `OR`보다 우선순위가 높음
- 조건: `(EMPNO > 100 AND SAL >= 3000) OR EMPNO = 200`

**조건 분석:**

| EMPNO | SAL | EMPNO > 100 | SAL >= 3000 | AND 결과 | EMPNO = 200 | 최종 (OR) |
|-------|-----|-------------|-------------|----------|-------------|-----------|
| 100 | 1000 | F | F | F | F | **F** |
| 200 | 3000 | T | T | **T** | **T** | **T** |
| 300 | 1500 | T | F | F | F | **F** |

**계산 과정:**

**EMPNO = 200:**
- `EMPNO > 100` → `200 > 100` → `T`
- `SAL >= 3000` → `3000 >= 3000` → `T`
- `(T AND T) OR T` → `T OR T` → `T` ✓

**결과:**
- 조건을 만족하는 행: 1개 (EMPNO = 200)
- `COUNT(*)` = **1**

**주의사항:**
- `AND`가 `OR`보다 우선순위 높음
- 괄호를 사용하면 명확하게 표현 가능

## 문제 7. Java 2차원 배열

### 문제 코드
```java

    public static void main(String[] args){
        int[][]arr = new int[][]{{45,50,75},{89}};
        System.out.println(arr[0].length);
        System.out.println(arr[1].length);
        System.out.println(arr[0][0]);
        System.out.println(arr[0][1]);
        System.out.println(arr[1][0]);
    }
}
```

### 정답
```
3
1
45
50
89
```

### 해설
**2차원 배열 구조:**

```
arr[0] = {45, 50, 75}  → 길이: 3
arr[1] = {89}          → 길이: 1
```

| 표현식 | 값 | 설명 |

| `arr[1][0]` | 89 | 두 번째 행, 첫 번째 열 |

**2차원 배열 시각화:**

```
arr[0]: [45][50][75]
         ↑   ↑   ↑
         0   1   2

arr[1]: [89]
         ↑
         0
```

**출력 순서:**
1. `arr[0].length` → **3**
2. `arr[1].length` → **1**
3. `arr[0][0]` → **45**
4. `arr[0][1]` → **50**
5. `arr[1][0]` → **89**

## 문제 8. 비정규화 (Denormalization)

### 문제
정규화된 엔티티, 속성, 관계에 대해 성능 향상과 개발 운영의 단순화를 위해 중복, 통합, 분리 등을 수행하는 데이터 모델링의 기법을 무엇이라고 하는지 쓰시오.

### 정답
**비정규화 (Denormalization) 또는 반정규화, 역정규화**

### 해설
**비정규화 특징:**

| 특징 | 설명 |
|------|------|
| **목적** | 성능 향상, 개발 운영 단순화 |
| **방법** | 중복, 통합, 분리 |
| **대상** | 정규화된 엔티티, 속성, 관계 |

**비정규화 방법:**

| 방법 | 설명 |
|------|------|
| **테이블 통합** | 관련 테이블을 하나로 통합 |
| **테이블 분할** | 테이블을 수평/수직 분할 |
| **중복 테이블 추가** | 조회 성능 향상을 위한 중복 테이블 |
| **중복 속성 추가** | 자주 조회되는 속성 중복 |

**정규화 vs 비정규화:**

| 구분 | 정규화 | 비정규화 |
|------|--------|---------|
| **목적** | 데이터 중복 제거 | 성능 향상 |
| **방향** | 분리 | 통합/중복 |
| **장점** | 데이터 일관성 | 조회 성능 |
| **단점** | 조인 증가 | 데이터 중복 |

**비정규화 적용 시점:**
- 조회 성능이 중요한 경우
- 조인이 많아 성능 저하
- 개발 운영 단순화 필요

## 문제 9. 블랙박스 테스트 기법

### 문제
다음은 블랙박스 기법에 대한 예제이다. 블랙박스 기법 두 가지를 쓰시오.

1. 0 <= x <= 10이면 -1 0 10 11 검사

2. 입력 데이터의 영역을 유사한 도메인별로 유효값 / 무효값을 그룹핑하여 나누어서 검사

### 정답
**1. 경계값 분석 (Boundary Value Analysis)**  
**2. 동등분할 테스트 (Equivalence Partitioning)**

### 해설
**블랙박스 테스트 기법:**

| 기법 | 설명 | 예시 |
|------|------|------|
| **경계값 분석** | 경계값에서 오류 발생 확률 높음 | 0 <= x <= 10 → -1, 0, 10, 11 |
| **동등분할** | 유사한 도메인별로 그룹핑 | 유효값/무효값 그룹 |
| **원인-효과 그래프** | 입력 간 관계 분석 | 원인-효과 그래프 작성 |
| **오류 예측** | 경험과 감각으로 테스트 | 과거 경험 활용 |
| **비교 검사** | 여러 버전 비교 | 동일 결과 확인 |

**1. 경계값 분석:**

**특징:**
- 경계값에서 오류 발생 확률 높음
- 최소값, 최대값, 경계 전후 값 테스트

**예시:**
- 범위: `0 <= x <= 10`
- 테스트 값: `-1, 0, 10, 11`
- 경계 전: `-1`
- 경계: `0, 10`
- 경계 후: `11`

**2. 동등분할 테스트:**

**특징:**
- 유사한 도메인별로 그룹핑
- 각 그룹에서 대표값 하나만 테스트
- 유효값/무효값 구분

**예시:**
- 유효값 그룹: `1~9`
- 무효값 그룹: `< 0`, `> 10`
- 각 그룹에서 대표값 선택

**블랙박스 테스트 비교:**

| 구분 | 경계값 분석 | 동등분할 |
|------|-----------|---------|
| **초점** | 경계값 | 그룹 내 대표값 |
| **효과** | 경계 오류 발견 | 테스트 수 감소 |
| **함께 사용** | 동등분할과 병행 | 경계값 분석과 병행 |

### 문제

1. IPv6는 (   1.   ) 비트 길이를 가진다.

2. IPv4는 길이 32bit이며, (   2.  ) 비트씩 네 부분으로 나눈다.

### 정답
**1. 128**  
**2. 8**

### 해설
**IPv4 vs IPv6:**

| 구분 | IPv4 | IPv6 |
|------|------|------|
| **주소 길이** | 32비트 | **128비트** |
| **표현 방식** | 10진수 (8비트씩 4부분) | 16진수 (16비트씩 8부분) |
| **주소 개수** | 약 43억 개 | 약 340간 개 |

**IPv4 주소 구조:**

```
32비트 = 8비트 × 4부분

예: 192.168.1.1
     └─┬─┘ └─┬─┘ └┬┘ └┬┘
      8비트  8비트 8비트 8비트
```

**IPv4 주소 표현:**

| 표현 | 설명 |
|------|------|
| **32비트** | 전체 주소 길이 |
| **8비트씩** | 네 부분으로 분할 |
| **10진수** | 각 부분을 10진수로 표현 (0~255) |

**IPv6 주소 구조:**

```
128비트 = 16비트 × 8부분

예: 2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

**주소 길이 비교:**

| 프로토콜 | 비트 수 | 바이트 수 | 표현 |
|---------|--------|----------|------|
| **IPv4** | 32비트 | 4바이트 | 192.168.1.1 |
| **IPv6** | **128비트** | 16바이트 | 2001:0db8::1 |

struct good {

void main(){
    struct good s[] = {"Kim",28,"Lee",38,"Seo",50,"Park",35};
    
    struct good *p;

}

Lee
38

```
s[0]: {"Kim", 28}
s[1]: {"Lee", 38}  ← p가 가리킴
s[2]: {"Seo", 50}
s[3]: {"Park", 35}
```

**출력:**
- `p->name` = `s[1].name` = `"Lee"`

## 문제 18. DAC (Discretionary Access Control)

### 문제
시스템 객체의 접근을 개인 또는 그룹의 식별자에 기반을 둔 방법, 어떤 종류의 접근 권한을 가진 사용자가 다른 사용자에 자신의 판단에 따라 권한을 허용하는 접근제어 방식은?

### 정답
**임의적 접근 통제 또는 DAC (Discretionary Access Control)**

### 해설
**접근 통제 유형:**

| 유형 | 약자 | 설명 | 특징 |
|------|------|------|------|
| **임의적 접근 통제** | DAC | 사용자 판단에 따라 권한 허용 | 사용자 제어 |
| **강제적 접근 통제** | MAC | 정책과 보안 등급 기반 | 시스템 제어 |
| **역할 기반 접근 통제** | RBAC | 역할에 기반한 접근 | 중앙 관리 |

**DAC 특징:**

| 특징 | 설명 |
|------|------|
| **기준** | 개인 또는 그룹의 식별자 |
| **제어** | 사용자가 판단하여 권한 허용 |
| **예시** | 파일 소유자가 권한 설정 |

**접근 통제 비교:**

**DAC (Discretionary Access Control):**
- 사용자 신분 기반
- 사용자가 권한 제어
- Unix/Linux 파일 권한

**MAC (Mandatory Access Control):**
- 정책과 보안 등급 기반
- 시스템이 강제 통제
- 군사 보안 등급

**RBAC (Role-Based Access Control):**
- 역할 기반
- 중앙에서 집중 관리
- 조직 내 역할 할당

**DAC 예시:**
```
파일 소유자: rwx (읽기, 쓰기, 실행)
그룹:        r-x (읽기, 실행)
기타:        r-- (읽기만)
```

## 문제 19. 결합도 (Coupling)

### 문제
다음은 결합도에 대한 설명이다. 빈칸에 들어갈 알맞은 용어를 보기에서 찾아 기호로 쓰시오.

1. 다른 모듈 내부에 있는 변수나 기능을 다른 모듈에서 사용하는 경우의 결합도

2. 모듈 간의 인터페이스로 배열이나 객체, 구조 등이 전달되는 경우의 결합도

3. 파라미터가 아닌 모듈 밖에 선언된 전역 변수를 참조하고 전역 변수를 갱신하는 식으로 상호작용하는 경우의 결합도

**보기:** 자료 결합도, 스탬프 결합도, 제어 결합도, 공통 결합도, 내용 결합도, 외부 결합도

### 정답
**1. 내용 결합도 (Content Coupling)**  
**2. 스탬프 결합도 (Stamp Coupling)**  
**3. 공통 결합도 (Common Coupling)**

### 해설
**결합도 순서 (나쁨 → 좋음):**

```
내용 결합도 > 공통 결합도 > 외부 결합도 > 제어 결합도 > 스탬프 결합도 > 자료 결합도
```

**결합도 비교표:**

| 결합도 | 설명 | 특징 |
|--------|------|------|
| **내용 결합도** | 다른 모듈 내부 변수/기능 사용 | 가장 나쁨 |
| **공통 결합도** | 전역 변수 참조 및 갱신 | 전역 변수 공유 |
| **외부 결합도** | 반환값을 다른 모듈에서 참조 | 외부 변수 참조 |
| **제어 결합도** | 제어 요소 전달 | 제어 흐름 전달 |
| **스탬프 결합도** | 배열, 객체, 구조 전달 | 복합 데이터 전달 |
| **자료 결합도** | 값만 전달 | 가장 좋음 |

**1. 내용 결합도:**

**특징:**
- 다른 모듈 내부 변수/기능 직접 사용
- 가장 강한 결합도
- 모듈 독립성 최소

**2. 스탬프 결합도:**

**특징:**
- 배열, 객체, 구조 등 복합 데이터 전달
- 필요한 데이터만 전달하지 않음
- 중간 정도 결합도

**3. 공통 결합도:**

**특징:**
- 전역 변수 참조 및 갱신
- 여러 모듈이 공통 데이터 공유
- 높은 결합도

**결합도 품질:**

| 결합도 | 품질 | 독립성 |
|--------|------|--------|
| 내용 결합도 | 최악 | 최소 |
| 공통 결합도 | 나쁨 | 낮음 |
| 외부 결합도 | 보통 | 보통 |
| 제어 결합도 | 보통 | 보통 |
| 스탬프 결합도 | 좋음 | 높음 |
| 자료 결합도 | 최고 | 최대 |

## 문제 20. 세션 하이재킹 (Session Hijacking)

### 문제
괄호 안에 공통으로 들어갈 공격 기법을 적으시오.

1. '세션을 가로채다' 라는 의미로 정상적 연결을 RST 패킷을 통해 종료시킨 후 재연결 시 희생자가 아닌 공격자에게 연결한다.

2. 세션 관리 취약점을 이용한 공격 기법이다.

### 정답
**세션 하이재킹 (Session Hijacking)**

### 해설
**세션 하이재킹 특징:**

| 특징 | 설명 |
|------|------|
| **의미** | 세션을 가로채다 |
| **방법** | RST 패킷으로 연결 종료 후 재연결 |
| **대상** | 세션 관리 취약점 |

**세션 하이재킹 공격 과정:**

```
[정상 연결]
[사용자] ←→ [서버]
    │
    ├─ RST 패킷 전송 (연결 종료)
    │
[공격자] ←→ [서버] (재연결)
```

**공격 단계:**

1. **정상 연결 감시**
   - 사용자와 서버 간 세션 감시

2. **RST 패킷 전송**
   - 정상 연결을 RST 패킷으로 종료

3. **재연결 가로채기**
   - 재연결 시 공격자에게 연결
   - 세션 ID 탈취

**세션 하이재킹 방어 방법:**

| 방법 | 설명 |
|------|------|
| **HTTPS 사용** | 암호화된 통신 |
| **세션 ID 암호화** | 세션 ID 보호 |
| **세션 타임아웃** | 짧은 세션 유지 시간 |
| **IP 검증** | IP 주소 변경 감지 |

**관련 공격 기법:**

| 공격 | 설명 |
|------|------|
| **세션 하이재킹** | 세션 가로채기 |
| **세션 고정** | 세션 ID 고정 |
| **세션 스푸핑** | 세션 ID 위조 |

**세션 관리 취약점:**
- 예측 가능한 세션 ID
- 세션 ID 노출
- 세션 타임아웃 부재
