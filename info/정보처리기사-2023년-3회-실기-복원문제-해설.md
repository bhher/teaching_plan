## 문제 1. Java 상속과 다형성

### 문제 코드
```java
public class main{
    public static void main(String[] args) {
        A b = new B();
        b.paint();
        b.draw();
    }
}
 
class A {
    public void paint() {
        System.out.print("A");
        draw();
    }
    public void draw() {
        System.out.print("B");
        draw();
    }
}
 
class B extends A {
    public void paint() {
        super.draw();
        System.out.print("C");
        this.draw();
    }
    public void draw() {
        System.out.print("D");
    }
}
```

### 정답
**BDCDD**

### 해설
**실행 과정:**

1. **객체 생성:**
   - `A b = new B()` → `b`는 A 타입이지만 B 인스턴스

2. **`b.paint()` 호출:**
   - `b`는 A 타입이지만 실제 객체는 B
   - **다형성**: B 클래스의 `paint()` 실행
   
   **B의 `paint()` 실행:**
   - `super.draw()` → A 클래스의 `draw()` 호출
     - A의 `draw()`: `System.out.print("B")` → **B** 출력
     - A의 `draw()` 내부: `draw()` 호출 → B의 `draw()` 실행 (다형성)
     - B의 `draw()`: `System.out.print("D")` → **D** 출력
   - `System.out.print("C")` → **C** 출력
   - `this.draw()` → B의 `draw()` 실행
     - B의 `draw()`: `System.out.print("D")` → **D** 출력

3. **`b.draw()` 호출:**
   - B의 `draw()` 실행
   - `System.out.print("D")` → **D** 출력

**실행 흐름:**

```
b.paint():
  super.draw() (A의 draw)
    → "B" 출력
    → draw() 호출 (B의 draw, 다형성)
      → "D" 출력
  → "C" 출력
  → this.draw() (B의 draw)
    → "D" 출력

b.draw():
  → "D" 출력
```

**출력 순서:**
1. B (super.draw()에서 A의 draw)
2. D (super.draw() 내부의 draw() 호출)
3. C (paint()에서)
4. D (this.draw())
5. D (b.draw())

**최종 출력: BDCDD**

**핵심 개념:**
- **메서드 오버라이딩**: 자식 클래스에서 부모 메서드 재정의
- **다형성**: 실제 객체의 메서드 호출
- **super**: 부모 클래스의 메서드 호출
- **this**: 현재 객체의 메서드 호출

## 문제 2. OAuth

### 문제
사용자가 사용자 이름 및 암호와 같은 자격 증명을 공유하지 않고도 타사 애플리케이션이 데이터 또는 리소스에 액세스할 수 있도록 권한을 부여할 수 있는 개방형 표준 프로토콜이다.

사용자가 데이터에 대한 제어를 유지하면서 리소스에 대한 액세스 권한을 부여할 수 있는 안전하고 표준화된 방법을 제공하며, 액세스 토큰을 사용하여 타사 애플리케이션에 리소스에 대한 액세스 권한을 부여하는 메커니즘을 사용자에게 제공하는 방식으로 작동한다.

사용자가 응용 프로그램에 대한 액세스 권한을 부여하면 응용 프로그램은 사용자를 대신하여 사용자의 리소스 또는 데이터에 액세스하는 데 사용할 수 있는 액세스 토큰을 받는다.

**보기:** ㄱ.NFT, ㄴ.JWT, ㄷ.SAML, ㄹ.accessToken, ㅁ.SSO, ㅂ.OIDC, ㅅ.Authentication, ㅇ.OAuth, ㅈ.Cookie, ㅊ.Refresh Token

### 정답
**ㅇ. OAuth**

### 해설
**OAuth 특징:**

| 특징 | 설명 |
|------|------|
| **목적** | 타사 애플리케이션에 리소스 접근 권한 부여 |
| **방식** | 액세스 토큰 사용 |
| **보안** | 자격 증명 공유 불필요 |
| **표준** | 개방형 표준 프로토콜 |

**OAuth 동작 과정:**

```
[사용자]                    [타사 앱]              [리소스 서버]
    │                           │                        │
    ├─ 권한 요청 ───────────────→│                        │
    │                           │                        │
    │←── 인증 페이지 ────────────┤                        │
    │                           │                        │
    ├─ 로그인 및 권한 승인 ──────→│                        │
    │                           │                        │
    │                           ├─ 액세스 토큰 요청 ────→│
    │                           │                        │
    │                           │←── 액세스 토큰 ────────┤
    │                           │                        │
    │                           ├─ 리소스 요청 (토큰) ───→│
    │                           │                        │
    │                           │←── 리소스 데이터 ───────┤
```

**OAuth vs 다른 인증 방식:**

| 방식 | 설명 | 특징 |
|------|------|------|
| **OAuth** | 권한 부여 프로토콜 | 액세스 토큰 사용 |
| **JWT** | 토큰 형식 | JSON 웹 토큰 |
| **SAML** | 인증/인가 프로토콜 | XML 기반 |
| **SSO** | 단일 로그인 | 한 번 로그인으로 여러 서비스 접근 |

**OAuth 활용:**
- 소셜 미디어 로그인 (Facebook, Twitter, LinkedIn)
- 클라우드 스토리지 서비스
- 온라인 마켓플레이스
- 금융 서비스

**OAuth 장점:**
- 향상된 보안 (자격 증명 공유 없음)
- 간소화된 애플리케이션 개발
- 사용자 제어 (권한 부여/취소)

## 문제 3. Linux 파일 권한 (chmod)

### 문제
리눅스(Linux)에서 사용자에게 읽기/쓰기/실행 권한을 부여하고, 그룹에게는 읽기/실행을 부여하고, 그 이외에는 실행 권한을 test.txt 파일에 부여하는 위한 명령어는 다음과 같다. 빈칸에 들어갈 답을 작성하시오. (8진법 사용)

### 정답
**(1) chmod**  
**(2) 751**

### 해설
**파일 권한 구조:**

| 권한 | 읽기(r) | 쓰기(w) | 실행(x) | 8진법 값 |
|------|---------|---------|---------|----------|
| **사용자(Owner)** | ✓ | ✓ | ✓ | 4+2+1 = **7** |
| **그룹(Group)** | ✓ | - | ✓ | 4+0+1 = **5** |
| **기타(Other)** | - | - | ✓ | 0+0+1 = **1** |

**권한 값 계산:**

```
사용자: rwx = 4 + 2 + 1 = 7
그룹:   r-x = 4 + 0 + 1 = 5
기타:   --x = 0 + 0 + 1 = 1

결과: 751
```

**chmod 명령어:**

```bash
chmod 751 test.txt
```

**파일 권한 표시:**

```
-rwxr-x--x  test.txt
│││││││││
││││││││└─ 기타: 실행(x)
│││││││└── 기타: -
││││││└─── 기타: -
│││││└──── 그룹: 실행(x)
││││└───── 그룹: -
│││└────── 그룹: 읽기(r)
││└─────── 사용자: 실행(x)
│└──────── 사용자: 쓰기(w)
└───────── 사용자: 읽기(r)
```

**8진법 권한 값:**

| 8진법 | 2진법 | 권한 | 설명 |
|------|------|------|------|
| 0 | 000 | --- | 권한 없음 |
| 1 | 001 | --x | 실행만 |
| 2 | 010 | -w- | 쓰기만 |
| 3 | 011 | -wx | 쓰기+실행 |
| 4 | 100 | r-- | 읽기만 |
| 5 | 101 | r-x | 읽기+실행 |
| 6 | 110 | rw- | 읽기+쓰기 |
| 7 | 111 | rwx | 모든 권한 |

## 문제 4. C언어 완전수 (Perfect Number)

### 문제 코드
```c
#include <stdio.h>
 
int test(int n) {
    int i, sum = 0;
 
    for (i = 1; i <= n / 2; i++){
        if (n % i == 0)
            sum += i;
    }
 
    if (n == sum) 
        return 1;
    
    return 0;
}
 
int main(){
    int i, sum=0;
 
    for (i = 2; i <= 100; i++){ 
        if (test(i))
            sum += i;
    }
    
    printf("%d ", sum); 
    return 0;
}
```

### 정답
**34**

### 해설
**완전수 (Perfect Number):**
- 자신을 제외한 약수의 합이 자신과 같은 수
- 예: 6 = 1 + 2 + 3

**test() 함수 동작:**
- 1부터 n/2까지 반복
- n의 약수를 찾아 합산
- 합이 n과 같으면 1 반환 (완전수)

**2부터 100까지 완전수 찾기:**

| 수 | 약수 (자신 제외) | 약수 합 | 완전수 여부 |
|---|----------------|---------|------------|
| 6 | 1, 2, 3 | 6 | ✓ |
| 28 | 1, 2, 4, 7, 14 | 28 | ✓ |
| 그 외 | - | - | ✗ |

**계산 과정:**

**6 검사:**
- 약수: 1, 2, 3
- 합: 1 + 2 + 3 = 6
- 완전수 ✓

**28 검사:**
- 약수: 1, 2, 4, 7, 14
- 합: 1 + 2 + 4 + 7 + 14 = 28
- 완전수 ✓

**합계:**
- `6 + 28 = 34`

**완전수 목록 (100 이하):**
- 6
- 28

**알고리즘:**
1. 각 수의 약수 찾기 (1부터 n/2까지)
2. 약수 합 계산
3. 합이 자신과 같으면 완전수
4. 완전수들의 합 계산

## 문제 5. C언어 구조체 포인터 접근 연산자

### 문제 코드
```c
#include <stdio.h>
#include <stdlib.h>
 
typedef struct Data{
    char c;
    int *numPtr; 
} Data;
 
int main(){
    int num = 10;
    Data d1;    
    Data *d2 = malloc(sizeof(struct Data));
    
    d1.numPtr = &num;  
    d2 ( ) numPtr = &num; 
 
    printf("%d\n", *d1.numPtr); 
    printf("%d\n", *d2 ( ) numPtr);
 
    free(d2); 
    return 0;
}
```

**출력 결과:**
```
10
10
```

### 정답
**→ (화살표 연산자)**

### 해설
**구조체 접근 방법:**

| 구분 | 구조체 변수 | 구조체 포인터 |
|------|-----------|--------------|
| **접근 연산자** | `.` (점) | `->` (화살표) |
| **예시** | `d1.numPtr` | `d2->numPtr` |

**코드 분석:**

1. **`d1.numPtr = &num`:**
   - `d1`은 구조체 변수
   - `.` 연산자로 멤버 접근

2. **`d2->numPtr = &num`:**
   - `d2`는 구조체 포인터
   - `->` 연산자로 멤버 접근

3. **`*d1.numPtr`:**
   - `d1.numPtr`은 `int*` 타입
   - `*` 연산자로 값 역참조

4. **`*d2->numPtr`:**
   - `d2->numPtr`은 `int*` 타입
   - `*` 연산자로 값 역참조

**메모리 구조:**

```
d1 (구조체 변수):
  c: [char]
  numPtr: → num (10)

d2 (구조체 포인터):
  → [구조체]
      c: [char]
      numPtr: → num (10)
```

**연산자 우선순위:**
- `->` 연산자가 `*` 연산자보다 우선순위 높음
- `*d2->numPtr` = `*(d2->numPtr)`

## 문제 6. SQL UNION 연산

### 문제
**테이블:**

**T1:**
| A |
|---|
| 3 |
| 1 |
| 4 |

**T2:**
| A |
|---|
| 2 |
| 4 |
| 3 |

**쿼리:**
```sql
SELECT A FROM T1
UNION
SELECT A FROM T2
ORDER BY A DESC;
```

### 정답
| A |
|---|
| 4 |
| 3 |
| 2 |
| 1 |

### 해설
**UNION 연산:**

| 연산 | 설명 | 특징 |
|------|------|------|
| **UNION** | 합집합 | 중복 제거 |
| **UNION ALL** | 합집합 | 중복 허용 |

**UNION 실행 과정:**

1. **T1과 T2 합치기:**
   - T1: {3, 1, 4}
   - T2: {2, 4, 3}
   - 합집합: {3, 1, 4, 2, 4, 3}

2. **중복 제거:**
   - {3, 1, 4, 2}

3. **ORDER BY A DESC:**
   - 내림차순 정렬
   - {4, 3, 2, 1}

**결과 테이블:**

| A |
|---|
| 4 |
| 3 |
| 2 |
| 1 |

**UNION vs UNION ALL:**

| 구분 | UNION | UNION ALL |
|------|-------|-----------|
| **중복** | 제거 | 허용 |
| **성능** | 느림 (정렬 필요) | 빠름 |
| **결과** | {1, 2, 3, 4} | {1, 2, 3, 3, 4, 4} |

## 문제 7. 접근 통제 (Access Control)

### 문제
**1.** 규칙 기반(Rule-Based) 접근통제 정책으로, 객체에 포함된 정보의 허용 등급과 접근 정보에 대하여 주체가 갖는 접근 허가 권한에 근거하여 객체에 대한 접근을 제한하는 방법이다.

**2.** 중앙 관리자가 사용자와 시스템의 상호관계를 통제하며 조직 내 맡은 역할(Role)에 기초하여 자원에 대한 접근을 제한하는 방법이다.

**3.** 신분 기반(Identity-Based) 접근통제 정책으로, 주체나 그룹의 신분에 근거하여 객체에 대한 접근을 제한하는 방법이다.

### 정답
**(1) MAC (Mandatory Access Control)**  
**(2) RBAC (Role-Based Access Control)**  
**(3) DAC (Discretionary Access Control)**

### 해설
**접근 통제 방식 비교:**

| 방식 | 설명 | 특징 | 관리자 |
|------|------|------|--------|
| **MAC** | 규칙 기반, 정보 등급 기반 | 강제적 접근 통제 | 시스템 |
| **DAC** | 신분 기반, 주체/그룹 기반 | 임의적 접근 통제 | 사용자 |
| **RBAC** | 역할 기반 | 역할에 따른 접근 | 중앙 관리자 |

**1. MAC (Mandatory Access Control):**

**특징:**
- 규칙 기반 접근 통제
- 정보의 허용 등급 기반
- 주체의 접근 허가 권한 기반
- 시스템이 강제적으로 통제

**예시:**
- 군사 보안 등급 (비밀, 기밀, 극비)
- 정보 등급과 주체 권한 비교

**2. RBAC (Role-Based Access Control):**

**특징:**
- 역할 기반 접근 통제
- 중앙 관리자가 통제
- 조직 내 역할에 기초
- 사용자에게 역할 할당

**예시:**
- 관리자, 일반 사용자, 게스트
- 역할별 권한 정의

**3. DAC (Discretionary Access Control):**

**특징:**
- 신분 기반 접근 통제
- 주체나 그룹의 신분 기반
- 사용자가 접근 권한 결정
- 임의적 접근 통제

**예시:**
- 파일 소유자가 권한 설정
- Unix/Linux 파일 권한

**접근 통제 비교표:**

| 구분 | MAC | DAC | RBAC |
|------|-----|-----|------|
| **통제 방식** | 강제적 | 임의적 | 역할 기반 |
| **기준** | 정보 등급 | 신분 | 역할 |
| **관리자** | 시스템 | 사용자 | 중앙 관리자 |
| **유연성** | 낮음 | 높음 | 중간 |

## 문제 8. C언어 팩토리얼 (Factorial)

### 문제 코드
```c
#include <stdio.h>
 
int f(int n) {
    if(n <= 1) return 1;
    else return n * f(n-1);
}
 
int main() {
    printf("%d", f(7));
}
```

### 정답
**5040**

### 해설
**팩토리얼 계산:**
- `n! = n × (n-1) × (n-2) × ... × 1`
- `7! = 7 × 6 × 5 × 4 × 3 × 2 × 1 = 5040`

**재귀 함수 실행:**

**f(7) 호출:**
```
f(7) = 7 × f(6)
f(6) = 6 × f(5)
f(5) = 5 × f(4)
f(4) = 4 × f(3)
f(3) = 3 × f(2)
f(2) = 2 × f(1)
f(1) = 1 (기저 조건)
```

**계산 과정:**

| 호출 | 계산 | 결과 |
|------|------|------|
| f(1) | 1 | 1 |
| f(2) | 2 × 1 | 2 |
| f(3) | 3 × 2 | 6 |
| f(4) | 4 × 6 | 24 |
| f(5) | 5 × 24 | 120 |
| f(6) | 6 × 120 | 720 |
| f(7) | 7 × 720 | **5040** |

**재귀 호출 스택:**

```
f(7)
  → f(6)
    → f(5)
      → f(4)
        → f(3)
          → f(2)
            → f(1) = 1
          = 2
        = 6
      = 24
    = 120
  = 720
= 5040
```

**팩토리얼 값:**

| n | n! |
|---|-----|
| 1 | 1 |
| 2 | 2 |
| 3 | 6 |
| 4 | 24 |

## 문제 11. Java 재귀 함수

### 문제 코드
```java
class Parent {
    int compute(int num) {
        if(num <= 1)
            return num;
        return compute(num-1) + compute(num-2);
    }
}
 
class Child extends Parent {
    int compute(int num) {
        if(num <= 1)
            return num;
        return compute(num-1) + compute(num-3);
    }
}
 
public class main {
    public static void main(String args[]) {
        Parent obj = new Child();
        System.out.print(obj.compute(7));
    }
}
```

### 정답
**2**

### 해설
**실행 과정:**

1. **객체 생성:**
   - `Parent obj = new Child()` → 실제 객체는 Child

2. **`obj.compute(7)` 호출:**
   - **다형성**: Child 클래스의 `compute()` 실행
   - `compute(7) = compute(6) + compute(4)`

**재귀 호출 트리:**

```
compute(7)
  = compute(6) + compute(4)
  
compute(6)
  = compute(5) + compute(3)
  
compute(5)
  = compute(4) + compute(2)
  
compute(4)
  = compute(3) + compute(1)
  = compute(3) + 1
  
compute(3)
  = compute(2) + compute(0)
  = compute(2) + 0
  
compute(2)
  = compute(1) + compute(-1)
  = 1 + (-1)
  = 0
  
compute(3) = 0 + 0 = 0
compute(4) = 0 + 1 = 1
compute(5) = 1 + 0 = 1
compute(6) = 1 + 0 = 1
compute(7) = 1 + 1 = 2
```

**계산 과정 표:**

| num | compute(num) | 계산 |
|-----|-------------|------|
| 0 | 0 | 기저 조건 |
| 1 | 1 | 기저 조건 |
| 2 | 0 | compute(1) + compute(-1) = 1 + (-1) = 0 |
| 3 | 0 | compute(2) + compute(0) = 0 + 0 = 0 |
| 4 | 1 | compute(3) + compute(1) = 0 + 1 = 1 |
| 5 | 1 | compute(4) + compute(2) = 1 + 0 = 1 |
| 6 | 1 | compute(5) + compute(3) = 1 + 0 = 1 |
| 7 | 2 | compute(6) + compute(4) = 1 + 1 = **2** |

**주의사항:**
- `compute(-1)`은 `-1 <= 1`이므로 `-1` 반환
- 음수 값도 처리됨

## 문제 13. Java static 메서드 오류

### 문제 코드
```java
class Person {
    private String name;
    public Person(String val) {
        name = val;
    }
    public static String get() {
        return name;  // 에러 발생
    }
    public void print() {

    }

public class main {
    public static void main(String[] args) {

    }
}
```

**7 (라인 7)**


## 문제 16. 동등 분할 테스트 (Equivalence Partitioning)

하나의 값은 그 분할 내 모든 값을 대표하는 것으로 간주하는 기법

모든 입력값을 시험할 필요가 없게 하여 시험을 효율적으로 수행하도록 지원

일반적으로 경계값 분석기법(boundary value analysis)과 함께 테스트 케이스 도출하는데 사용

**보기:** ㄱ.Equivalence Partitioning, ㄴ.Statement Coverage, ㄷ.Boundary Value Analysis, ㄹ.Branch Coverage, ㅁ.Error Guessing, ㅂ.Condition Coverage, ㅅ.Cause Effect Graph

### 정답
**ㄱ. Equivalence Partitioning (동등 분할)**

### 해설
**동등 분할 테스트 특징:**

| 특징 | 설명 |
|------|------|
| **원리** | 유사한 입력값은 유사한 결과 |
| **방법** | 입력값을 그룹으로 분류 |
| **효과** | 테스트 효율성 향상 |
| **활용** | 경계값 분석과 함께 사용 |

**동등 분할 예시:**

**입력값: 나이 (0~120)**

| 분할 | 범위 | 대표값 | 설명 |
|------|------|--------|------|
| 유효 | 1~17 | 10 | 미성년자 |
| 유효 | 18~64 | 30 | 성인 |
| 유효 | 65~120 | 80 | 노인 |
| 무효 | < 0 | -5 | 음수 |
| 무효 | > 120 | 150 | 범위 초과 |

**테스트 케이스:**
- 각 분할에서 대표값 하나만 테스트

|------|---------|-----------|

| **효과** | 테스트 수 감소 | 경계 오류 발견 |

## 문제 17. 클라우드 서비스 모델

### 문제
다이어그램을 보고 괄호안에 알맞는 답을 보기에 골라 작성하시오.

**보기:** PaaS, SaaS, IaaS

### 정답
**(1) IaaS (Infrastructure as a Service)**  
**(2) PaaS (Platform as a Service)**  
**(3) SaaS (Software as a Service)**

### 해설
**클라우드 서비스 모델 비교:**

| 모델 | 설명 | 제공 내용 | 사용자 관리 |
|------|------|----------|------------|
| **IaaS** | 인프라 서비스 | 하드웨어, 네트워크 | OS, 미들웨어, 애플리케이션 |
| **PaaS** | 플랫폼 서비스 | 인프라 + 플랫폼 | 애플리케이션 |
| **SaaS** | 소프트웨어 서비스 | 전체 스택 | 없음 |

**클라우드 서비스 모델 계층:**

```
[애플리케이션]        ← SaaS (사용자: 없음)
[플랫폼/미들웨어]     ← PaaS (사용자: 애플리케이션)
[OS]                 ← IaaS (사용자: OS, 미들웨어, 애플리케이션)
[인프라/하드웨어]     ← IaaS 제공
```

**각 모델 설명:**

**1. IaaS (Infrastructure as a Service):**
- 가상화된 하드웨어 제공
- 서버, 스토리지, 네트워크
- 예: AWS EC2, Azure Virtual Machines

**2. PaaS (Platform as a Service):**
- 개발 플랫폼 제공
- 런타임, 데이터베이스, 미들웨어
- 예: Heroku, Google App Engine

## 문제 18. RIP (Routing Information Protocol)

### 문제
최소 Hop count를 파악하여 라우팅하는 프로토콜이다.

거리와 방향으로 길을 찾아가는 Distance Vector 다이나믹 프로토콜이다.

최단거리 즉, Hop count가 적은 경로를 택하여 라우팅하는 프로토콜로 Routing Table에 인접 라우터 정보를 저장하여 경로를 결정한다.

최대 Hop count는 15로 거리가 짧기 때문에 IGP로 많이 이용하는 프로토콜이다.

### 정답
**RIP (Routing Information Protocol)**

### 해설
**RIP 특징:**

| 특징 | 설명 |
|------|------|
| **타입** | Distance Vector 프로토콜 |
| **기준** | Hop count (최소) |
| **최대 Hop** | 15 |
| **사용 범위** | IGP (내부 게이트웨이) |
| **업데이트** | 30초마다 |

**RIP 동작:**

```
[라우터 A]          [라우터 B]          [라우터 C]
    │                   │                   │
    ├─ 라우팅 테이블 ────→│                   │
    │ (인접 라우터 정보) │                   │
    │                   ├─ 라우팅 테이블 ───→│
    │                   │                   │
    └─ 최소 Hop 경로 선택 ─┴───────────────────┘
```

**RIP 라우팅 테이블:**

| 목적지 | 다음 홉 | Hop Count |
|--------|--------|-----------|
| 네트워크1 | 라우터B | 1 |
| 네트워크2 | 라우터C | 2 |
| 네트워크3 | 라우터B | 3 |

**RIP vs 다른 라우팅 프로토콜:**

| 프로토콜 | 타입 | 기준 | 최대 Hop |
|---------|------|------|----------|
| **RIP** | Distance Vector | Hop count | 15 |
| **OSPF** | Link State | 비용 | 무제한 |
| **BGP** | Path Vector | 경로 속성 | 무제한 |

**RIP 제한사항:**
- 최대 Hop count: 15
- 큰 네트워크에 부적합
- 느린 수렴 속도

**RIP 장점:**
- 구현이 간단
- 작은 네트워크에 적합
- IGP로 널리 사용

## 문제 19. 관계대수 연산자

### 문제
1. join: (   1   )
2. project: (   2   )
3. select: (   3   )
4. division: (   4   )

**보기:** ㄱ. σ, ㄴ. π, ㄷ. ⋈, ㄹ. ÷

### 정답
**(1) ㄷ. ⋈ (조인)**  
**(2) ㄴ. π (프로젝션)**  
**(3) ㄱ. σ (선택)**  
**(4) ㄹ. ÷ (나눗셈)**

### 해설
**관계대수 연산자:**

| 연산 | 기호 | 설명 | 예시 |
|------|------|------|------|
| **선택** | σ | 조건에 맞는 행 선택 | `σ조건(R)` |
| **프로젝션** | π | 특정 속성 선택 | `π속성(R)` |
| **조인** | ⋈ | 두 릴레이션 결합 | `R1 ⋈ R2` |
| **나눗셈** | ÷ | 나눗셈 연산 | `R1 ÷ R2` |

**1. 조인 (Join): ⋈**

**특징:**
- 두 릴레이션을 결합
- 공통 속성 기준

**예시:**
```
R1 ⋈ R2
```

**2. 프로젝션 (Projection): π**

**특징:**
- 특정 속성만 선택
- 중복 제거

**예시:**
```
π이름, 전공(학생)
```

**3. 선택 (Selection): σ**

**특징:**
- 조건에 맞는 행 선택
- 필터링

**예시:**
```
σ학년=3(학생)
```

**4. 나눗셈 (Division): ÷**

**특징:**
- 나눗셈 연산
- 복잡한 쿼리 표현

**예시:**
```
R1 ÷ R2
```

**관계대수 연산자 표:**

| 연산자 | 기호 | 유니코드 |
|--------|------|---------|
| 선택 | σ | U+03C3 |
| 프로젝션 | π | U+03C0 |
| 조인 | ⋈ | U+22C8 |
| 나눗셈 | ÷ | U+00F7 |

**기본 연산:**
- 선택 (σ)
- 프로젝션 (π)
- 합집합 (∪)
- 차집합 (-)
- 카티션 곱 (×)

**파생 연산:**
- 조인 (⋈)
- 나눗셈 (÷)
- 교집합 (∩)

## 문제 20. 참조 무결성 (Referential Integrity)

### 문제
(            ) 무결성은 관계 데이터베이스 관계 모델에서 2개의 관련 있던 관계 변수(테이블) 간의 일관성(데이터 무결성)을 말한다.

종종 기본 키 또는 키가 아닌 후보 키와 외래 키의 조합으로 강제 적용된다.

외래 키가 선언된 관계 변수의 외래 키를 구성하는 속성(열)의 값은 그 관계 변수의 부모가 되는 관계 변수의 기본 키 값 또는 기본 키가 아닌 후보 키 값으로 존재해야 한다.

### 정답
**참조 (Referential)**

### 해설
**참조 무결성 특징:**

| 특징 | 설명 |
|------|------|
| **목적** | 테이블 간 일관성 유지 |
| **방법** | 외래 키 제약조건 |
| **규칙** | 외래 키는 부모 키 값이어야 함 |

**참조 무결성 구조:**

```
[부모 테이블]              [자식 테이블]
학과                      학생
├─ 학과코드 (PK)          ├─ 학번 (PK)
└─ 학과명                 ├─ 이름
                          └─ 학과코드 (FK) → 학과.학과코드
```

**참조 무결성 규칙:**

| 규칙 | 설명 |
|------|------|
| **삽입** | 외래 키 값은 부모 테이블에 존재해야 함 |
| **수정** | 외래 키 값 변경 시 부모 테이블에 존재해야 함 |
| **삭제** | 부모 키 삭제 시 제약 (CASCADE, RESTRICT 등) |

**참조 무결성 예시:**

**학과 테이블:**
| 학과코드 | 학과명 |
|---------|--------|
| C001 | 컴퓨터공학 |
| C002 | 전자공학 |

**학생 테이블:**
| 학번 | 이름 | 학과코드 |
|------|------|---------|
| 1001 | 김철수 | C001 ✓ |
| 1002 | 이영희 | C002 ✓ |
| 1003 | 박민수 | C999 ✗ (참조 무결성 위반) |

**참조 무결성 위반:**
- 외래 키 값이 부모 테이블에 존재하지 않음
- 삽입/수정 시 오류 발생

**참조 무결성 제약조건:**

```sql
CREATE TABLE 학생 (
    학번 INT PRIMARY KEY,
    이름 VARCHAR(20),
    학과코드 INT,
    FOREIGN KEY (학과코드) REFERENCES 학과(학과코드)
);
```
