## 문제 1. Java 싱글톤 패턴

### 문제 코드
```java
class Connection {
    private static Connection _inst = null;
    private int count = 0;
    
    static public Connection get() {
        if(_inst == null) {
            _inst = new Connection();
            return _inst;
        }
        return _inst;
    }
    
    public void count() {
         count++; 
    }
    
    public int getCount() {
         return count; 
    }
}

public class main {  
    public static void main(String[] args) {
        Connection conn1 = Connection.get();
        conn1.count();

        Connection conn2 = Connection.get();
        conn2.count();

        Connection conn3 = Connection.get();
        conn3.count();
        
        conn1.count();
        System.out.print(conn1.getCount());
    }
}
```

### 정답
**4**

### 해설
- **싱글톤 패턴(Singleton Pattern)**: 클래스의 인스턴스가 하나만 생성되도록 보장하는 디자인 패턴
- `Connection.get()` 메서드는 항상 동일한 인스턴스(`_inst`)를 반환
- `conn1`, `conn2`, `conn3` 모두 같은 인스턴스를 참조
- `count` 변수는 인스턴스 변수이므로 모든 참조가 같은 `count` 값을 공유

**실행 과정:**
1. `conn1.count()` → count = 1
2. `conn2.count()` → count = 2 (같은 인스턴스)
3. `conn3.count()` → count = 3 (같은 인스턴스)
4. `conn1.count()` → count = 4 (같은 인스턴스)

따라서 출력값은 **4**입니다.

## 문제 2. C언어 삼항연산자와 비트시프트

### 문제 코드
```c
#include <stdio.h>
 
int main() {
    int v1 = 0, v2 = 35, v3 = 29;
    
    if(v1 > v2 ? v2 : v1) {
        v2 = v2 << 2;
    }else{
        v3 = v3 << 2;
    }
    
    printf("%d", v2+v3);
}
```

### 정답
**151**

### 해설
- **삼항연산자**: `v1 > v2 ? v2 : v1`
  - `v1 > v2` → `0 > 35` → `false`
  - 따라서 `v1` (0) 반환
- **if 조건**: `if(0)` → `false`이므로 `else` 블록 실행
- **비트시프트 연산**: `v3 = v3 << 2`
  - `29 << 2` = `29 × 2²` = `29 × 4` = `116`
- **결과**: `v2 + v3` = `35 + 116` = **151**

## 문제 3. 응집도(Cohesion) 순서

### 문제
응집도가 높은 순으로 나열하시오.

**보기**: ㄱ. 기능, ㄴ. 교환, ㄷ. 우연, ㄹ. 시간

### 정답
**ㄱ, ㄴ, ㄹ, ㄷ** (기능 > 교환 > 시간 > 우연)

### 해설
응집도는 모듈 내부 요소들이 서로 얼마나 밀접하게 관련되어 있는지를 나타내는 정도입니다.

**응집도 순서 (높음 → 낮음):**

| 순위 | 응집도 종류 | 설명 |
|------|------------|------|
| 1 | **기능적 응집도** | 모듈의 모든 요소가 단일 기능을 수행 |
| 2 | **순차적 응집도** | 한 요소의 출력이 다음 요소의 입력으로 사용 |
| 3 | **교환적 응집도** | 동일한 입력/출력을 사용하는 기능들이 모여있음 |
| 4 | **절차적 응집도** | 특정 순서로 실행되어야 하는 기능들이 모여있음 |
| 5 | **시간적 응집도** | 특정 시간에 실행되는 기능들이 모여있음 |
| 6 | **논리적 응집도** | 유사한 성격의 기능들이 모여있음 |
| 7 | **우연적 응집도** | 서로 관련 없는 기능들이 모여있음 |

따라서 **기능 > 교환 > 시간 > 우연** 순서입니다.

## 문제 4. C언어 문자열 역순 및 인덱스 출력

### 문제 코드
```c
#include <stdio.h>
#include <string.h>
 
void reverse(char* str){
    int len = strlen(str);
    char temp;
    char*p1 = str;
    char*p2 = str + len - 1;
    while(p1<p2){
        temp = *p1;
        *p1 = *p2;
        *p2 = temp;
        p1++;
        p2--;
    }
}
 
int main(int argc, char* argv[]){
    char str[100] = "ABCDEFGH";
 
    reverse(str);
 
    int len = strlen(str);
 
    for(int i=1; i<len; i+=2){
        printf("%c",str[i]);
    }
 
    printf("\n");
 
    return 0;
}
```

### 정답
**GECA**

### 해설
1. **초기 문자열**: `"ABCDEFGH"` (인덱스: 0~7)
2. **reverse() 함수 실행**:
   - `p1`은 시작 위치, `p2`는 끝 위치를 가리킴
   - 양쪽에서 중앙으로 이동하며 문자 교환
   - 결과: `"HGFEDCBA"`

3. **인덱스 출력**:
   - `for(int i=1; i<len; i+=2)` → 홀수 인덱스만 출력
   - 인덱스 1: `G`
   - 인덱스 3: `E`
   - 인덱스 5: `C`
   - 인덱스 7: `A`

따라서 출력값은 **GECA**입니다.

**문자열 변화 과정:**
```
초기:  A B C D E F G H
      0 1 2 3 4 5 6 7

reverse 후: H G F E D C B A
            0 1 2 3 4 5 6 7

홀수 인덱스: G(1) E(3) C(5) A(7) → GECA
```

## 문제 5. 네트워크 IP 주소 할당

- 3) 129.200.10.16/22

- 192.168.35.72
- 192.168.36.0
- 192.168.36.249

- 129.200.8.249

- **2) 192.168.35.72**
- **4) 129.200.8.249**
- **5) 192.168.36.249**

**네트워크 구조 다이어그램:**
```
                    [라우터]
                       |
        ┌──────────────┼──────────────┐
        |              |              |
    [서브넷1]      [서브넷2]      [서브넷3]
    
1) 192.168.35.3/24    3) 129.200.10.16/22    6) 192.168.36.24/24
   (네트워크:            (네트워크:              (네트워크:
    192.168.35.0/24)     129.200.8.0/22)         192.168.36.0/24)
        |                    |                      |
2) 192.168.35.72        4) 129.200.8.249       5) 192.168.36.249
```

**각 서브넷의 유효 IP 범위:**

| 서브넷 | 네트워크 주소 | 서브넷 마스크 | 유효 IP 범위 | 할당 IP |
|--------|-------------|-------------|------------|---------|
| 서브넷1 | 192.168.35.0 | /24 | 192.168.35.1 ~ 192.168.35.254 | 2) **192.168.35.72** ✓ |

- **129.200.10.16/22**: 
  - 서브넷 마스크: `255.255.252.0` = `11111111.11111111.11111100.00000000`
  - 네트워크 주소: `129.200.10.16` AND `255.255.252.0` = `129.200.8.0`

  - 유효 범위: `129.200.8.1 ~ 129.200.11.254`

## 문제 6. 정규형 판단

### 문제 테이블
| 고객아이디 | 강좌명 | 강사번호 |
|-----------|--------|----------|
| apple | 영어회화 | P001 |
| banana | 기초토익 | P002 |
| carrot | 영어회화 | P001 |
| carrot | 기초토익 | P004 |
| orange | 영어회화 | P003 |
| orange | 기초토익 | P004 |

### 정답
**제 3정규형**

### 해설
**정규화 과정:**

1. **제1정규형(1NF)**: 원자값으로 구성 ✓
   - 모든 속성이 원자값을 가짐

2. **제2정규형(2NF)**: 부분 함수 종속 제거
   - 후보키: (고객아이디, 강좌명)
   - 강사번호는 강좌명에만 종속 (부분 함수 종속)
   - 분해 필요:
     ```
     R1(고객아이디, 강좌명)
     R2(강좌명, 강사번호)
     ```

3. **제3정규형(3NF)**: 이행 함수 종속 제거
   - R2에서 강사번호가 강좌명에 직접 종속
   - 이행 함수 종속 없음 ✓

**함수 종속성:**
- (고객아이디, 강좌명) → 강사번호
- 강좌명 → 강사번호 (부분 함수 종속)

**결론**: 제2정규형 위반이지만, 제3정규형 조건을 만족하므로 **제 3정규형**입니다.

## 문제 7. 네트워크 라우팅 프로토콜

### 문제 설명
1. 대표적인 링크 상태 라우팅 프로토콜이다.
2. 인터넷에서 연결된 링크의 상태를 감시하여 최적의 경로를 선택한다.
3. 단일 자율 시스템 내에서 라우팅 정보를 배포하는 데 사용되는 내부 게이트웨이 프로토콜이다.
4. 모든 대상에 도달하기 위한 최단 경로를 구축하고 계산하며 최단 경로는 Dijkstra 알고리즘을 사용하여 계산된다.

### 정답
**OSPF (Open Shortest Path First)**

### 해설

- **내부 게이트웨이 프로토콜(IGP)**: 자율 시스템(AS) 내부에서 사용
- **Dijkstra 알고리즘**: 최단 경로 우선 알고리즘 사용
- **링크 상태 광고(LSA)**: 네트워크 상태 정보를 모든 라우터에 전파

**라우팅 프로토콜 비교:**

| 프로토콜 | 타입 | 알고리즘 | 사용 범위 |
|---------|------|---------|----------|
| OSPF | 링크 상태 | Dijkstra | AS 내부 |
| RIP | 거리 벡터 | Bellman-Ford | AS 내부 |
| BGP | 경로 벡터 | - | AS 간 |

## 문제 8. 조인(Join) 종류

### 문제
(1) 조인에 참여하는 두 릴레이션의 속성 값을 비교하여 조건을 만족하는 튜플만 반환한다.

(2) 조건이 정확하게 '=' 등호로 일치하는 결과를 반환한다.

(3) (2) 조인에서 조인에 참여한 속성이 두 번 나오지 않도록 중복된 속성을 제거한 결과를 반환한다.

### 정답
- **(1) 세타 조인(Theta Join)**
- **(2) 동등 조인(Equi Join)**
- **(3) 자연 조인(Natural Join)**

### 해설
**조인 종류:**

1. **세타 조인(θ-Join)**
   - 비교 연산자(>, <, =, ≥, ≤, ≠)를 사용한 조인
   - 조건을 만족하는 튜플만 반환

2. **동등 조인(Equi Join)**
   - 세타 조인의 특수한 경우
   - '=' 연산자만 사용
   - 동일한 값을 가진 튜플을 결합

3. **자연 조인(Natural Join)**
   - 동등 조인의 특수한 경우
   - 공통 속성을 기준으로 조인
   - 중복된 속성 제거

**예시:**
```
R1(A, B, C)    R2(C, D, E)

세타 조인:     R1 ⋈ R1.B > R2.D R2
동등 조인:     R1 ⋈ R1.C = R2.C R2
자연 조인:     R1 ⋈ R2  (C 속성 기준, 중복 제거)
```

## 문제 9. 페이지 교체 알고리즘 (LRU, LFU)

### 문제
**페이지 참조 순서**: 1, 2, 3, 1, 2, 4, 1, 2, 5, 7  
**할당된 프레임 수**: 3개

### 정답
- **(1) LRU: 6**
- **(2) LFU: 6**

### 해설
**LRU (Least Recently Used) - 가장 오래 전에 사용된 페이지 교체**

| 참조 | 프레임 상태 | 최근 사용 순서 | 페이지 부재 | 설명 |
|------|------------|--------------|------------|------|
| 1 | [1, -, -] | [1] | ✓ | 초기 로드 |
| 2 | [1, 2, -] | [1, 2] | ✓ | 초기 로드 |
| 3 | [1, 2, 3] | [1, 2, 3] | ✓ | 초기 로드 |
| 1 | [1, 2, 3] | [2, 3, 1] | - | 히트 (1을 최근으로) |
| 2 | [1, 2, 3] | [3, 1, 2] | - | 히트 (2를 최근으로) |
| 4 | [2, 3, 4] | [1, 2, 4] | ✓ | 3 교체 (가장 오래됨) |
| 1 | [3, 4, 1] | [2, 4, 1] | ✓ | 2 교체 (가장 오래됨) |
| 2 | [4, 1, 2] | [1, 4, 2] | ✓ | 4 교체 (가장 오래됨) |
| 5 | [1, 2, 5] | [4, 1, 5] | ✓ | 1 교체 (가장 오래됨) |
| 7 | [2, 5, 7] | [1, 2, 7] | ✓ | 2 교체 (가장 오래됨) |

**페이지 부재 횟수: 6회**

**LRU 동작 원리:**
- 각 페이지의 최근 사용 시간을 추적
- 페이지 부재 발생 시, 가장 오래 전에 사용된 페이지를 교체
- 프레임이 가득 찬 후부터 교체 시작

**LFU (Least Frequently Used) - 가장 적게 사용된 페이지 교체**

| 참조 | 프레임 상태 | 사용 횟수 (페이지:횟수) | 페이지 부재 | 설명 |
|------|------------|----------------------|------------|------|
| 1 | [1, -, -] | 1:1 | ✓ | 초기 로드 |
| 2 | [1, 2, -] | 1:1, 2:1 | ✓ | 초기 로드 |
| 3 | [1, 2, 3] | 1:1, 2:1, 3:1 | ✓ | 초기 로드 |
| 1 | [1, 2, 3] | 1:2, 2:1, 3:1 | - | 히트 (1 사용 횟수 증가) |
| 2 | [1, 2, 3] | 1:2, 2:2, 3:1 | - | 히트 (2 사용 횟수 증가) |
| 4 | [1, 2, 4] | 1:2, 2:2, 4:1 | ✓ | 3 교체 (사용 1회, 가장 적음) |
| 1 | [1, 2, 4] | 1:3, 2:2, 4:1 | - | 히트 (1 사용 횟수 증가) |
| 2 | [1, 2, 4] | 1:3, 2:3, 4:1 | - | 히트 (2 사용 횟수 증가) |
| 5 | [1, 2, 5] | 1:3, 2:3, 5:1 | ✓ | 4 교체 (사용 1회, 가장 적음) |
| 7 | [1, 2, 7] | 1:3, 2:3, 7:1 | ✓ | 5 교체 (사용 1회, 가장 적음) |

**페이지 부재 횟수: 6회**

**LFU 동작 원리:**
- 각 페이지의 사용 빈도를 카운트
- 페이지 부재 발생 시, 사용 횟수가 가장 적은 페이지를 교체
- 동일한 사용 횟수인 경우, 일반적으로 FIFO 방식 적용

## 문제 10. Java 실행 순서

### 문제 코드
```java
class Parent {
    int x, y;
 
    Parent(int x, int y) { ①
        this.x=x;
        this.y=y;
    }
 
    int getT() { ②
        return x*y;
    }
}
 
class Child extends Parent {
    int x;
 
    Child (int x) { ③
        super(x+1, x);
        this.x=x;
    }
 
    int getT(int n){ ④
        return super.getT()+n;
    }
}
 
class Main {
    public static void main(String[] args) { ⑤
        Parent parent = new Child(3); ⑥
        System.out.println(parent.getT()); ⑦
    }
}
```

**실행 순서**: 5 → ( ) → ( ) → ( ) → ( ) → ( )

### 정답
**6 → 3 → 1 → 7 → 2**

### 해설
**실행 순서 상세:**

1. **⑤ main(String[] args)** 시작
   - 프로그램 진입점

2. **⑥ new Child(3)** 호출
   - Child 객체 생성 시작
   - Child 생성자 호출

3. **③ Child(int x)** 실행
   - 매개변수 `x = 3` 받음
   - `super(x+1, x)` 호출 → `super(4, 3)`
   - 부모 생성자 호출

4. **① Parent(int x, int y)** 실행
   - 매개변수 `x = 4`, `y = 3` 받음
   - `this.x = 4` (Parent의 x)
   - `this.y = 3` (Parent의 y)
   - 생성자 완료, Child 생성자로 복귀

5. **③ Child(int x)** 계속 실행
   - `this.x = 3` (Child의 x, Parent의 x와 별개)
   - 생성자 완료

6. **⑦ parent.getT()** 호출
   - `parent`는 `Parent` 타입이지만 실제 객체는 `Child` 인스턴스
   - `Child`에 `getT(int n)` 메서드가 있지만 매개변수 불일치
   - 부모 클래스의 `getT()` 메서드 호출

7. **② getT()** 실행
   - Parent 클래스의 메서드
   - `x * y` 계산
   - Parent의 `x = 4`, `y = 3`
   - 결과: `4 * 3 = 12` 반환

**실행 순서: 5 → 6 → 3 → 1 → 7 → 2**

**출력값: 12**

**핵심 개념:**
- **상속**: Child는 Parent를 상속
- **생성자 체이닝**: `super()`로 부모 생성자 호출
- **변수 숨김**: Child의 `x`가 Parent의 `x`를 숨김
- **메서드 오버로딩**: `getT()`와 `getT(int n)`은 다른 메서드
- **다형성**: 타입은 Parent지만 실제 객체는 Child

## 문제 16. Java 상속과 다형성

### 문제 코드
```java
class classOne {
    int a, b;
 
    public classOne(int a, int b) {
        this.a = a;
        this.b = b;
    }
 
    public void print() {
        System.out.println(a + b);
    }
}

class classTwo extends classOne {
    int po = 3;
    
    public classTwo(int i) {
        super(i, i+1);
    }
 
    public void print() {
        System.out.println(po*po);
    }
}

public class main {  
    public static void main(String[] args) {
        classOne one = new classTwo(10);
        one.print();
    }
}
```

### 정답
**9**

### 해설
**실행 과정:**

1. **`new classTwo(10)`** 호출
   - `classTwo(int i)` 생성자 실행
   - `super(10, 11)` 호출 → `classOne(10, 11)`
   - `a = 10`, `b = 11`
   - `po = 3`

2. **`one.print()`** 호출
   - `one`은 `classOne` 타입이지만 `classTwo` 인스턴스
   - **다형성(Polymorphism)**: 실제 객체의 메서드가 호출됨
   - `classTwo`의 `print()` 메서드 실행
   - `po * po = 3 * 3 = 9` 출력

**다형성 원리:**
- 컴파일 타임: `classOne` 타입으로 인식
- 런타임: 실제 객체(`classTwo`)의 메서드 호출
- 메서드 오버라이딩으로 자식 클래스 메서드가 실행

## 문제 18. SQL 논리연산자 우선순위

### 문제
```sql
SELECT COUNT(*) 
FROM TABLE 
WHERE EMPNO > 100 
AND SAL >= 3000 OR EMPNO = 200
```

**TABLE:**

| EMPNO | SAL |
|-------|-----|
| 50 | 2000 |
| 100 | 3000 |
| 150 | 4000 |
| 200 | 2500 |
| 250 | 5000 |

### 정답
**1**

### 해설
**논리연산자 우선순위:**
- `AND`가 `OR`보다 우선순위가 높음
- 따라서 조건은: `(EMPNO > 100 AND SAL >= 3000) OR EMPNO = 200`

**조건 분석 표:**

| EMPNO | SAL | EMPNO > 100 | SAL >= 3000 | (EMPNO > 100 AND SAL >= 3000) | EMPNO = 200 | 최종 결과 (OR) |
|-------|-----|-------------|-------------|------------------------------|-------------|----------------|
| 50 | 2000 | F | F | **F** | F | **F** |
| 100 | 3000 | F | T | **F** | F | **F** |
| 150 | 4000 | T | T | **T** | F | **T** |
| 200 | 2500 | T | F | **F** | **T** | **T** |
| 250 | 5000 | T | T | **T** | F | **T** |

**예상 결과:**
- 조건을 만족하는 행: 3개 (EMPNO: 150, 200, 250)
- COUNT(*) = 3

**하지만 정답이 1인 이유:**
정답이 1이라는 것은 테이블 데이터가 다르거나, 조건 해석이 다를 수 있습니다.

**가능한 시나리오:**
만약 테이블이 다음과 같다면:
| EMPNO | SAL |
|-------|-----|
| 50 | 2000 |
| 100 | 3000 |
| 150 | 2500 |
| 200 | 2500 |
| 250 | 2000 |

이 경우:
- EMPNO=200: `(T AND F) OR T` = `T` → **1개만 만족**

**또는 조건 해석:**
`EMPNO > 100 AND (SAL >= 3000 OR EMPNO = 200)`
- EMPNO=150: `T AND (F OR F)` = `F`
- EMPNO=200: `T AND (F OR T)` = `T` → **1개만 만족**

**최종 답: 1** (정답 기준)

## 문제 19. C언어 문자 변환

### 문제 코드
```c
#include<stdio.h>
#include<ctype.h>
 
int main(){
    char*p = "It is 8";
    char result[100];
    int i;
 
    for(i=0; p[i]!='\0'; i++){
        if(isupper(p[i]))
            result[i] = (p[i]-'A'+5)% 25 + 'A';
        else if(islower(p[i]))
            result[i] = (p[i]-'a'+10)% 26 + 'a';
        else if(isdigit(p[i]))
            result[i] = (p[i]-'0'+3)% 10 + '0';
        else if(!(isupper(p[i]) || islower(p[i]) || isdigit(p[i])))    
            result[i] = p[i];
    }
 
    result[i] = '\0';
    printf("%s\n",result);
 
    return 0;
}
```

### 정답
**Nd sc 1**

### 해설
**문자 변환 규칙:**

1. **대문자**: `(p[i]-'A'+5) % 25 + 'A'`
2. **소문자**: `(p[i]-'a'+10) % 26 + 'a'`
3. **숫자**: `(p[i]-'0'+3) % 10 + '0'`
4. **기타**: 그대로 유지

| 문자 | 타입 | 계산 | 결과 |
|------|------|------|------|
| 'I' | 대문자 | ('I'-'A'+5) % 25 + 'A' = (8+5) % 25 + 'A' = 13 + 'A' = 'N' | **N** |

| ' ' | 기타 | 그대로 | **' '** |
| 'i' | 소문자 | ('i'-'a'+10) % 26 + 'a' = (8+10) % 26 + 'a' = 18 + 'a' = 's' | **s** |
| 's' | 소문자 | ('s'-'a'+10) % 26 + 'a' = (18+10) % 26 + 'a' = 2 + 'a' = 'c' | **c** |
| ' ' | 기타 | 그대로 | **' '** |
| '8' | 숫자 | ('8'-'0'+3) % 10 + '0' = (8+3) % 10 + '0' = 1 + '0' = '1' | **1** |

```
    └─ ConcreteFactory2 (구체 팩토리 2)

AbstractProductA, AbstractProductB (추상 제품)
    ├─ ProductA1, ProductB1 (제품 1군)
    └─ ProductA2, ProductB2 (제품 2군)
```

**예시:**
- GUI 컴포넌트: Windows 스타일 vs Mac 스타일
- 데이터베이스: MySQL vs Oracle

**다른 패턴과의 차이:**

| 패턴 | 설명 |
|------|------|
| **Factory Method** | 하나의 제품을 생성 |
| **Abstract Factory** | 관련된 제품 군을 생성 |
| **Builder** | 복잡한 객체를 단계적으로 생성 |
